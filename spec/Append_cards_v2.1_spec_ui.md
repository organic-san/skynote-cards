# Skynote — v2.1 UI 規格

> 本文件是 `Append_cards_v2_spec.md` 的 UI 附錄。**介面部分與 v2 衝突時以本文件為準**；資料模型、rel 矩陣、規則語義完全不動，本次沒有任何 domain 改動。
>
> **編號規則**：`U` 開頭是 UI 決議，與 domain 的 `R` 分開兩套命名空間，不互相引用編號。一經指派永不重編，作廢的號碼也不重用。
>
> A–F 是版面與流程，G 是視覺規範與 token。被本文件修訂或撤回的 v2 條目集中列在 H 節；I 節記錄已裁決、不要再繞回來的做法。
>
> 反芻期的 UI（v2 D.5）**不在本次範圍**，但 U12 先留好位置，屆時不需重排版面。

---

## A. 型別的呈現

**U24. 型別 `original` 的 UI 標籤由「原始」改為「資料」。**
只改介面用字，domain 的型別名 `original` 不動，卡片檔與解析器完全不受影響。適用範圍：列表 meta 行、首頁篩選列、關聯區塊、表單的型別標示。側欄的「追加外部資料」用字不變，改名後與它一致。

**U1. 型別以左側色點標示，並且一律附上無色的型別名。**
色點負責一眼分辨，文字負責記得住——顏色本身不可記憶，不得單獨承擔型別資訊。型別名使用與日期相同的次要灰階，不上色、不加框。原本的彩色外框徽章全部移除。

**U6. 色點對照表。**

| type | UI 標籤 | 色點 |
|---|---|---|
| `original` | 資料 | 實心藍 `#4A7FB5` |
| `restatement` | 重述 | 實心綠 `#4F9D69` |
| `thinking` | 思考 | 實心琥珀 `#D99A2B` |
| `fleeting` | 碎片 | 空心灰環 `#9CA3AF`，內部透明 |

`fleeting` 用空心是原本虛線徽章那個「尚未定案」語義的延續，是唯一的形狀例外。空心在視覺上比實心輕，環的邊寬取 2px 補回重量（見 U27 的等重要求）。

**U7. 首頁的型別篩選列各項前方也放同一顆色點。**
這是使用者學會色彩對應的唯一場所，成本一顆點。

## B. 列表項

現行列表用「彩色外框徽章 + 全寬分隔線」做兩件事：標示型別、切開項目。兩者都偏重，合併成一件事處理（U1）。

**U2. 列表項之間不使用分隔線，改用間距。**
項目間距 32px；標題→摘要 4px；摘要→meta 行 8px。色點同時是項目起點的視覺錨，分界由它與間距共同承擔。

**U3. 列表項採兩欄。**
左欄固定寬 72px：色點（直徑 8px）+ 日期，色點與日期間距 8px。右欄：標題、內文前兩行、meta 行。左欄的左緣即內容欄的左緣，右欄形成第二條對齊線，整份列表只有這兩條垂直線。

**U4. 日期格式。**

| 時間 | 顯示 |
|---|---|
| 今天 | `今天` |
| 昨天 | `昨天` |
| 兩天以前（同年） | `09-04` |
| 跨年 | `2025-09-04` |

只有今天與昨天有體感差異，值得換成相對說法；再遠一律回到日期。

卡片**主體**（標題底下那條 meta）一律顯示絕對日期與時間，不套用此表——那是這張卡的事實，不該用「今天」這種會過期的說法記錄。卡片頁上的關聯區塊（含「你在這裡」那一行）不在此列，照樣套用此表：那裡的時間是拿來跟上下游比先後的，用相對說法才讀得出關係。

**U5. meta 行的內容依型別（沿用 v2 A.6，補上型別名的位置）。**
型別名固定在 meta 行第一段，其餘欄位以 `·` 分隔：

| type | meta 行 |
|---|---|
| `original` | `資料 · 作者 · 原始年份 · N 則重述 / M 則引用`（作者或年份缺漏整段略過） |
| `restatement` | `重述 · 它在講哪份資料` |
| `thinking` | `思考 · 出向 N · 入向 M` |
| `fleeting` | `碎片`（標題即全部內容，無摘要行） |

`source_date` 是自由字串，照原樣顯示，與作者同一個灰階，不要與 `created` 使用相同樣式。

## C. 側邊欄

**U8. 「碎片」更名為「雜筆」。**
只改側欄這份工作清單的名稱。型別的 UI 標籤仍是「碎片」。改名的理由是消歧義：側欄那項是「fleeting 且無入向連結」，首頁篩選列的「碎片」是全部 fleeting，同名不同集合會讓兩處數字對不起來。

**U9. 移除四份清單後面的數量。**
這些清單實務上不會歸零，數字提供不了「還剩多少」的訊號，只是每次進站都在閃一個不會變的數。清單本身的長度就是它的量。

**U10. 「追加外部資料」與「標籤」「搜尋」維持相同格式。**
撤回 v2 B 節「刻意不一致」的設計。實測那個版本壓力偏重；它已經在分隔線下方的動作與工具區，位置本身足以表達它不是去處。

**U11. 卡片索引（側欄下半的全卡列表）保留，但降低視覺重量。**
它的用途是**建立連結時的名稱參照**，不是導覽——所以它屬於下半的工具區，不與上半的工作狀態競爭。作法：
- 上方加一行小標「卡片索引」，讓它的職責在畫面上可讀，不再看起來像第二份清單。
- 標題文字改為與側欄其他項目相同的灰階，移除現行那個只在此處出現的藍色連結色。
- 字級比工作清單小一級。

## D. 卡片詳細頁

**U12. 閱讀順序：卡片內容在前，關聯區塊在後。**
現行把關聯樹放在標題之上，一進頁面先讀到後設資料，而且標題的垂直位置隨連結多寡浮動，頁面沒有固定落點。改為：

```
返回
標題
meta 行
內文
──────────
關聯區塊
```

meta 行格式：`思考 · 2026-09-04 16:01`。反芻期上線後在同一行末尾追加第三段（`可修改 3 小時` / `已定案`），不加框、不做倒數跳動——位置先留著。

**U13. 關聯區塊維持縱向的體感式結構。**
上游在上、下游在下，中間是「你在這裡」，方向由**空間位置**表達而不是由文字說明表達。這是刻意的設計，不改成兩組並列的清單。

```
  關聯自  資料：一個值得參考的資料             09-04
↑ 1
你在這裡
↓ 2
  更新至  思考：我覺得這兩者可以被連繫再一起   09-04
  延伸至  思考：我想到了什麼                 09-04
```

**U13a. 引用串攤平成一維的軌道。**（修訂 U13 的實作，語意不變）
巢狀 `<ul>` 加 `border-left` 的縮排被推翻。原因是展開鈕落在「比父深、比子淺」的縮排上，不屬於任何一層，眼睛沒辦法把它歸給誰；而上游要向上長，又得靠三層 `column-reverse` 加一條補丁把容器整個翻過來。

改成：伺服器直接依**視覺順序**輸出一維的列（上游就是下游那串的反序），縮排由每一列自己畫的軌道表達，展開鈕併回它自己那一列的行尾。

代價講明白，兩項：

- **一列必須是一行。** 軌道要連續，列與列之間就不能有間距，行距只能靠固定列高給。因此中文標題超出寬度時以 `…` 截斷。
- **收合改由 JS 做。** `<details>` 的位置沒了，收合變成 class 切換。沒有 JS 時仍看得到預設深度（上 1 下 2），但展不開。

```
  關聯自  資料：一個值得參考的資料                    09-04 16:01
↑ 1
你在這裡：這張卡的標題              全部展開   09-04 16:02
↓ 2
  更新至  思考：我覺得這兩者可以被連繫再一起  ▾ 2      09-04 16:03
  ├─ 延伸出  思考：我想到了什麼                        09-04 16:20
  └─ 支撐出  碎片：一個隨興的想法，長的話就截…         09-04 17:44
```

「你在這裡」本身也是一列：同樣的列高、同樣的截斷、同樣的相對日期加時刻。上下游既然都是等高的列，原點要是自成一種樣子就會從那條節奏裡掉出來。它的時間戳記與卡片主體那條絕對時間是兩個用途——那條說「這張卡是什麼時候寫的」，這條說「它在這一串裡排在哪」。

`全部展開` 掛在同一行，因為那是唯一一個同時看得到上下游的位置；串裡沒有任何可展開的節點時不出現。

- 每列格式：`rel` + `型別：標題` + 日期。型別名連寫在標題前，列首依 U1 置色點；日期套 U4。
- `↑ n` / `↓ n` 是展開深度指示，同時是展開控制點。
- **預設展開往上 1 層、往下 2 層**，再深的層級由使用者手動點開。截圖裡的多層縮排是手動展開後的狀態，不是預設。
- 卡片本身沒有任何連結時，兩側不留空欄，只顯示「你在這裡」一行。

## E. 表單

**U14. 每個建立表單頂端要有動作標題。**
現行只有一個型別標示，沒有任何一行說明這是什麼動作。格式：
- 從全域進入：`追加外部資料`、`隨手記`
- 從卡片 `+` 進入：`從《對於這個意見我有一些新想法》發想`

這行同時滿足 v2 C.4 對來源可見的要求，且在送出**前**就看得到。

**U15. 連結的目標一律顯示標題，ID 不外露。**
v2 C.1/C.3 的整套設計目的就是使用者永遠不必碰 ID。現行把 18 位數 ID 當欄位主值、標題縮成下方灰字，主次相反。手動新增的連結列：輸入框接受 ID 或標題（搜尋既有行為維持），**選定之後該列改為顯示標題**，ID 收進 title 屬性或完全不顯示。

**U16. 由 `+` 選單預填的那條連結是唯讀列。**
依 v2 C.3，該連結不可刪除、只能改 rel。因此該列：只有 rel 下拉可操作，目標顯示為標題文字（非輸入框），**不出現減號**。使用者手動新增的列維持現行行為：一列一個減號，按 `+` 才長出新的空列——空列是手動產物，不做自動追加也不做自動清理。

**U17. 表單的垂直節奏。**
標籤→欄位 12px；欄位→下一組標籤 40px。現行兩者相近，整份表單讀起來是一疊等距方框，眼睛沒有落腳點。
`original` 表單再依主次分兩段：主群組（標題 / 網址 / 內文）與次群組（作者 / 原始年份 / 來源標記 / 連結 / 標籤），兩段之間留 56px。

**U18. 隨手記顯示「將存為什麼」。**
送出鍵上方一行灰字，隨標題欄即時更新：`將存為 碎片` / `將存為 思考`。這不是多一次決策（v2 C.2 的生死線不動），只是把已經做完的判斷顯示出來。

## F. 版面

**U19. 內容欄靠左對齊，寬度可由使用者調整。**
距側欄右緣固定 80px，欄寬預設 640px。置中會讓整個版面右漂、側欄與內容看起來不屬於同一個版面。
欄寬是**預設值不是上限**：右緣可拖動調整，分割視窗的中線同樣可拖動。兩者的位置分別記在本機，重開沿用。表單欄寬跟隨閱讀欄的當前寬度。

**U20. 頁面頂距統一 56px。**
分割視窗的左側來源面板同樣適用，現行它幾乎貼著視窗上緣。

**U21.（作廢）** 曾規定 `border` 只給可互動表面。過於獨斷，撤回；邊框的使用逐個元件判斷。編號不重用。

**U22. `+` 按鈕的位置依裝置分。**
桌機錨在內容欄的右下角，不再貼視窗角落——現行兩者相距一大片空白，「從這張卡建立」的語義關聯被距離稀釋。手機維持右下浮動，符合 v2 C.3 的單手可及。

**U23. `+` 選單的浮層保留陰影。**
實測有陰影的版本視覺上較好，維持。陰影值見 U31。

## G. 視覺規範

### G.1 字體

**U25. 字體二分：介面用黑體，卡片內容用宋體。**
卡片標題與內文用思源宋體（Noto Serif TC）；側欄、按鈕、meta 行、表單標籤、關聯區塊用黑體（Noto Sans TC / system-ui）。
現行整站同一套無襯線，側欄、按鈕、正文是同一種材質，畫面沒有「這裡是文件、那裡是工具」的分別。這條分界跟 v2 B 節「工作狀態 vs 動作與工具」是同一條，只是換成字體來表達。
中文宋體標題的字重取 **600**，不用 700——700 會讓筆畫在小字級下糊成一團。

**U26. 所有數字使用等寬數字。**
日期、計數、ID 一律 `font-variant-numeric: tabular-nums`。列表左欄的日期要靠這條才會在每一列落在同一個位置，形成 U3 說的第二條對齊線；比例數字做不到。

### G.2 色彩

**U27. 四個型別色是畫面上唯一的彩色，其餘一律中性灰階。**
推論出來的三條：

- **連結不使用藍色。** 資料（`original`）的色點是藍的，兩個藍語義無關卻搶同一個色彩位置。連結改為接近黑的文字，hover 時加底線。
- **四色需要等重校正。** 現行琥珀在視覺上明顯比藍重，同一份列表裡思考卡會不成比例地跳出來。四色在 OKLCH 上對齊亮度與彩度（目標 L≈0.62、C≈0.11），U6 的十六進位值是校正前的起點，實作時以校正後的值覆蓋並回填 U6 的表。
- **`::selection` 用當前卡片的型別色 12% 透明度。** 選取文字在這個系統裡是「引用選取的段落」的前置動作，讓它帶型別色是有語義的。

### G.3 排版尺度

**U28. 字級只有四級，中文行高高於英文習慣。**

| 級 | 用途 | 行高 |
|---|---|---|
| 13px | meta 行、側欄次要、卡片索引 | 1.5 |
| 15px | 列表摘要、側欄項目、表單標籤 | 1.6 |
| 17px | 卡片內文、列表標題 | 1.8 |
| 22px | 卡片標題 | 1.4 |

不得出現第五級。中文文字加 `letter-spacing: 0.02em`，拉丁與數字維持 0。

**U29. 所有間距取自同一組尺度：`4 / 8 / 12 / 16 / 24 / 32 / 40 / 56 / 80`。**
不在這組裡的數值不得使用。本條追溯調整了兩個先前的值：U2 的項目間距 28→32、U17 的群組間距 36→40。

**U30. 色點採光學對齊。**
色點的垂直位置對齊標題第一行的**視覺中心**，不是行框中心也不是 cap height 的算術中點——直接算會偏高約 1px，需要手動補償。這 1px 是「看起來有做過」與「兜出來的」的分界。

### G.4 表面與狀態

**U31. 用紙感分層，陰影一律兩層。**
頁面底色為極淡的暖白 `#FCFBF9`，浮層與輸入框為純白 `#FFFFFF`；兩者的明度差本身就在做分層，陰影只是加強。
陰影固定為兩層疊加：`0 1px 2px rgba(0,0,0,.04)` + `0 8px 24px rgba(0,0,0,.06)`。單層陰影不管怎麼調都會有塑膠感，兩層是因為它模擬的是接觸陰影加環境陰影。

**U32. 互動狀態要補齊。**

- **hover**：列表項給極淡底色，且向左右各溢出 16px（超出文字欄），讓它看起來是一塊可點區域而不是文字變色。
- **focus**：2px 描邊、2px offset，不使用瀏覽器預設樣式。全站鍵盤可達。
- **selected**：側欄當前項用底色塊，字重不變。
- **空狀態**：一句與 meta 同灰階的話，不放插圖、不放按鈕。

**U33. 動效只出現在浮層，120–160ms。**
`+` 選單與隨手記浮層從 `scale(0.96)` 展開，`transform-origin` 設在觸發按鈕那一角，讓它看起來是從按鈕長出來的；ease-out，不用彈跳。列表、頁面切換、展開關聯區塊一律不加動畫。必須實作 `prefers-reduced-motion`。

### G.5 中文網頁排版

**U34. 下列四項為必要設定。**

- `line-break: strict` — 避免標點跑到行首。
- `text-wrap: pretty` — 避免最後一行只剩一兩個字。
- 內文前兩行的截斷用 `-webkit-line-clamp`，並確認省略號不會單獨成行。
- 側欄卡片索引的捲軸做細捲軸樣式，非 hover 時隱藏。

### G.6 Token

**U35. 上述數值集中成一份 token 表，是樣式的唯一真相來源。**
不得在元件裡寫死顏色、間距、字級、陰影、動效時間。這條與 v2 F 節「per-type 的差異集中在表格資料裡」是同一條紀律，只是對象換成樣式值。

| 類別 | 值 |
|---|---|
| 間距 | `4 / 8 / 12 / 16 / 24 / 32 / 40 / 56 / 80` |
| 字級 | `13 / 15 / 17 / 22` |
| 行高 | `1.4 / 1.5 / 1.6 / 1.8` |
| 字距 | 中文 `0.02em`、拉丁與數字 `0` |
| 文字色 | 主 `#1A1A1A`、次 `#6B6B6B`、弱 `#9B9B9B` |
| 表面 | 頁面 `#FCFBF9`、浮層與輸入框 `#FFFFFF`、分隔線 `#E8E5E0` |
| 型別色 | 見 U6（以 U27 校正後的值為準） |
| 圓角 | 欄位與按鈕 `6px`、浮層 `10px` |

## I. 已裁決的邊界

**卡片索引不移除。** 曾提議刪掉側欄下半的全卡列表，理由是它是儲存分類、與 v2 B 節的工作狀態打架。未採用：它的實際用途是建立連結時查名稱，屬於工具而非導覽。改為以 U11 降重並標明職責。

**色點不取代型別文字。** 顏色不易記憶，單靠色點會讓型別在介面上再次消失（正是 v2 A.6 要修的問題）。色點是加速器，文字才是資訊來源。

**關聯區塊不改成兩組並列的清單。** 曾提議取消 `↑ n` / `↓ n` 記號、改用「指向這張卡 / 這張卡指向」兩個組標題。未採用：縱向的上下游加上「你在這裡」是體感式的，方向由位置表達比由文字表達直接。遞迴展開也保留，只是預設深度收斂為上 1 下 2（U13）。

**空的連結列不是缺陷。** 它是使用者按 `+` 產生的，維持現行行為。

**邊框沒有全域規則。** 見作廢的 U21。曾想把 border 限縮到可互動表面，過於獨斷；逐個元件判斷。
