## 1. 背景

### 1.1 要回應的觀察

v3 草案 2 §1 記錄了設計假設與實際用法的落差，其中兩項由環境回應：

1. **跨分野的雜訊。** 首頁是一條混著所有主題的時間軸，不同脈絡的內容互相干擾。
2. **缺一個放的地方。** 還留在 Discord 的幾種用法（TODO、紀錄、想做的事、旅遊紀錄），缺的幾乎都是同一樣東西：一個放的地方。

原則與 v3 相同：**機制只提供原件，流程留在使用習慣裡。** v3 補的原件是勾選，本版補的是環境。

### 1.2 檢驗方式

環境上線後，把 TODO 與紀錄從 Discord 搬進來。一個月後（2026-12 初）檢查這兩樣還在不在 Discord：還在，代表這個方向沒有解決問題，應停止投入。

## 2. 環境

### 2.1 定義

**一個環境就是一份完整的 Skynote。** 它有自己的首頁時間軸、標籤、搜尋與隨手記。在一個環境裡看不到其他環境的卡片。

- **劃分的依據是專注脈絡**，例如：雜事與資料、繪圖、學校、專題、自我省思、故事與創意發想。同一個環境裡可以混用 TODO、紀錄與思考。
- **各環境的規則完全一致。** 型別、rel 矩陣、反芻期、定案，在每個環境都相同。規則那一層不知道環境存在，所以這是結構上的保證，不靠紀律維持。
- **連結可以跨環境。** 例如專題最早的發想，來自故事與創意發想。
- **既有的卡屬於「（無環境）」，那是過渡的狀態**（§2.3）：預期整批搬進環境，搬空了它就不再出現。
- **環境不是標籤的另一種呈現。** 標籤與空間混用會讓兩者都變得雜亂，所以環境是標籤之上、真正分離的一層。

### 2.2 資料配置與名稱

環境就是 `cards/` 底下的一層資料夾：

```
corpus/
  cards/
    {id}.md            ← （無環境）：既有的卡，搬空之前留在這裡
    繪圖/{id}.md       ← 環境「繪圖」
    學校/{id}.md       ← 環境「學校」
  envs.yml             ← 側欄裡環境的先後（§2.8）；在環境面板裡拖曳時寫入
  tags.yml
```

- **環境的身分就是資料夾名稱，卡片檔不記錄自己在哪個環境。** frontmatter 一個欄位都不加，既有的卡不必改寫，日後搬動也不必改內容。
- **ID 全域唯一。** 發號時的碰撞檢查看過每一個資料夾（`store/files.ts` 的 `cardExists`）。原本的 `fileExistsTaken` 只看 `cards/` 這一層，已移除。
- **依 ID 找檔案不靠索引**（`findCard`）。檔案是唯一真相，索引只是投影。環境只有幾個，逐一資料夾問一次就夠。先找（無環境），其餘依環境名稱。
- **資料夾只有一層。** 環境底下的資料夾不會被讀，重建報告會列出來（§2.9）。以 `.` 開頭的資料夾不算環境。
- **有哪些環境由資料夾決定，不另設清單。** 先後可以在環境面板裡拖曳排定，記在 `envs.yml`（§2.8）；那個檔只記順序，對不到資料夾的名字略過，沒列到的環境照最近一張卡接在後面。

**名稱規則**（`service/envs.ts` 的 `checkEnvName`）。語料庫會被 clone 到別的系統上手動整理，所以比 Linux 檔名嚴格：

- 去掉首尾空白、統一成 NFC 之後不得為空。
- 不得含 `/ \ < > : " | ? *` 與控制字元。
- 不得以 `.` 開頭，也不得以 `.` 結尾（Windows 不允許）。
- 不得是 Windows 的保留裝置名（`CON`、`PRN`、`AUX`、`NUL`、`COM1`–`COM9`、`LPT1`–`LPT9`，帶副檔名也算）。
- 最多 40 字。
- 不得與其他環境同名，**不分大小寫**：Windows 與 macOS 的檔案系統裡，`Draw` 與 `draw` 是同一個資料夾。

這些只約束從網頁建立與改名的環境。在別處手動開的資料夾，名字只要不是以 `.` 開頭，照樣是環境。

### 2.3 （無環境）是過渡的狀態

- **側欄**：（無環境）有卡才列；搬空了就不列。介面上的名稱是「（無環境）」，括號讓它不像一個真的環境，字也退一階。它不在環境面板裡，也不參與排序，總是在排過的環境後面（§2.8）。
- **網址**：它沿用既有的網址（`/`、`/tags`、`/search`、`/new`），既有書籤與測試不受影響。
- **搬空之後**：它的頁面（GET）導向最近寫過東西的那個環境，查詢字串照樣帶著——`/tags?sort=name` 導到 `/e/{環境}/tags?sort=name`。舊書籤照樣能用，隨手記也不會在一個看不見的地方寫下新卡。還沒有任何環境時不導向，跟以前一樣。導向的是最近寫過的，不是側欄排第一的：排序是使用者定的先後，打開首頁要接著寫的是剛才在寫的地方。
- **不能改名**：它不是資料夾。
- **搬移的方式**：在別處的 clone 開好資料夾、`git mv` 進去、push，再按側欄的「更新」（v3 §7）。取回、重建之後，卡片就在新的環境裡；有 bucket 時對帳會把新名字傳上去、舊名字刪掉（§2.10）。

### 2.4 網址與目前所在的環境

- **（無環境）**：既有網址全部不變。
- **環境**：加上前綴 `/e/{環境}/`，其下是同一組路由：`/e/{環境}/`、`/tags`、`/search`、`/new`、`/quick`。`/e/{環境}` 導到結尾有斜線的那一個；不存在的環境回 404「沒有這個環境」。
- **卡片頁** `/c/{id}` 與編輯頁維持全域，不帶環境。頁面的外殼（側欄、標籤連結、返回、`+` 選單）以這張卡所屬的環境為目前環境。
- **不記憶上次所在的環境**，伺服器不保存這個狀態。想直接進某個環境，把它的網址存成書籤。

用網址前綴而不用 cookie：網址可以存書籤、可以同時開兩個分頁各看一個環境，而且伺服器維持無狀態。

**草稿槽**（v2.2 §2）帶上環境，否則兩個環境的隨手記會共用同一格。（無環境）維持原來的名字，既有的草稿照樣找得到；環境的槽名加上 `{環境}|` 前綴（`繪圖|quick`、`繪圖|quick:tag:構圖`、`繪圖|new:original`、`繪圖|new:thinking:expand`）。`|` 不會出現在環境名稱裡。以卡片 ID 為鍵的槽（`edit:{id}`、`new:{type}:{rel}:{srcId}`）不受影響。

### 2.5 各功能的範圍

| 功能 | 範圍 | 說明 |
|---|---|---|
| 首頁時間軸、型別與標籤篩選 | 目前環境 | |
| 標籤頁、表單的標籤推薦 | 目前環境 | 同名標籤在不同環境各算各的 |
| 側欄下半的最近標籤與最近卡片 | 目前環境 | 卡片頁的外殼以那張卡所屬的環境為目前環境 |
| 隨手記 | 目前環境 | 寫進目前所在的環境 |
| 搜尋頁 | 目前環境，可切到所有環境 | 見下 |
| 標籤鎖定（`tags.yml`） | 全域 | 維持根目錄一份 |
| 卡片 ID、`/c/{id}`、段落錨點 `#b{n}` | 全域 | |
| 連結、卡片頁的上下游串 | 全域 | 別的環境的卡標出環境名 |
| 連結選卡器（`/api/search`） | 全域 | 目前環境的排在前面，別的環境的標出環境名 |
| 定案（R6） | 全域 | 被任何環境的卡指向都會定案 |
| 側欄的「更新」（v3 §7） | 全域 | 取回的是整個語料庫 |

**搜尋的範圍**：搜尋框底下一組跟篩選列同樣式的切換，「{目前環境的名字}」與「所有環境」，預設是前者。切到所有環境時網址帶 `all=1`，換關鍵字、換型別篩選都留著。只有一個環境時沒有東西可切，不出現。

**別的環境的卡**在搜尋結果、上下游串、選卡器裡標出環境名：一個淡底的小籤（`.envmark`），它說的是「這張卡放在哪裡」，跟型別名、標籤不是同一種東西。同一個環境的卡不標。搜尋結果上的標籤連回那張卡所在的環境，因為標籤以環境為界。

### 2.6 新卡落在哪個環境

- **隨手記（含展開之後的思考與產出）、追加外部資料、裸的 `/new`**：目前所在的環境，由網址決定，表單上不問。
- **卡片頁的 `+`**：預設是來源卡的環境，表單上可以改選（型別那一行底下的「環境」選單）。跨環境衍生是明確的需求（§2.1）。只有一個環境可選時不問。
- 表單選的環境在送出時已經不在（例如剛被改名），就退回表單說明原因，不寫到別的地方。
- **建立之後不能改環境**，反芻期內也不行。放錯了就刪除重建（R9）：一般卡片限反芻期內，產出在被引用之前都可以（v3 §3）。
- **標籤繼承**（v2 C.3）照舊。標籤只是卡片上的字串，跨環境衍生時會計入新環境的統計。

### 2.7 建立與改名

**建立**（環境面板底下的名稱欄，`POST /envs`）：開一個資料夾，然後進到那個環境。

- 空資料夾不會進 git，也不會進 bucket（bucket 沒有資料夾）。沒有卡片的環境沒有東西需要備份；App Engine 換機器時它就不在了，寫進第一張卡才留得住。
- 不寫進 `envs.yml`：沒排過的環境本來就接在側欄的後面。
- 名稱不合格或重複時，說原因，附一條回到原本環境的路。

**改名**（環境面板裡每一列的鉛筆，`POST /envs/rename`）：資料夾換名字。

- 卡片的內容逐位元不變，ID、連結、`/c/{id}` 都不變；變的是環境的網址，舊的 `/e/{舊名}/` 不再存在。
- **改完回到按下去時所在的那一頁**（瀏覽器帶來的 Referer）。面板裡每個環境都能改，改的多半不是正在看的那一個，被帶去別的地方會莫名其妙。那一頁在被改名的環境底下，就換成新名字的網址（`/e/繪圖/tags` → `/e/插畫/tags`）；卡片頁不帶環境，原樣回去。只認同一個站、讀得回來的頁面（首頁、標籤、搜尋、建立表單、卡片頁、編輯頁），其他情況進到改好的那個環境。沒改成時，說明頁留在按下去時所在的環境（表單的 `at`）。
- **順序**：排過序的話，`envs.yml` 裡的舊名字換成新名字，位置不變，跟卡片在同一個 commit。
- 跟卡片的寫入走同一把寫入鎖，改到一半不會有卡寫進舊資料夾。
- **git**：整個資料夾一個 commit，訊息是 `env {舊名} → {新名}`。這是「一張卡一個 commit」唯一的例外。commit 時照卡片的 ID 去 stage（不管它現在在哪個資料夾），不照資料夾：連著改兩次名、或一件修改的 commit 排在改名後面，輪到它們的時候資料夾已經換了名字，照資料夾 stage 會推上一個只有刪除、整個環境都不見的版本（§2.10 的對帳會把它當真）。卡片的 commit（`add`、`edit`、`check`、`rm`）也照 ID stage，理由相同。
- **bucket**（有設定時）：每一張卡用新名字存一份，全部成功才刪舊名字；存到一半失敗就把已經存的收回來，什麼都不改（503）。新名字一律標成「這個路徑上的新寫入」（base 是 none），推上去了沒有交給對帳去問：改名還沒推上 GitHub 就換了機器時，開機對帳問的是剛 clone 下來的歷史，那才是真的推上去了什麼。推過的卡在舊資料夾原樣回來，新名字那份內容相同，當成搬走留下的刪掉，乾淨地回到改名之前；沒推過的寫入不在那份歷史裡，取回新資料夾。不能拿本機的 git 歷史判斷：它含 push 失敗、還沒推上去的 commit，換機器之後那些卡會被當成舊的刪掉。
- （無環境）不能改名。新名字與舊名字相同時什麼都不做；只差大小寫可以改。

環境的刪除與卡片在環境之間的移動，本版不提供介面，見 v3.2 草案。

### 2.8 側欄

```
Skynote
首頁                ← 目前環境的時間軸
─────────
環境            ⚙   ← 齒輪打開環境面板
  寫作              ← 目前所在的環境：底色標起來
  學習與記憶
  繪圖
  （無環境）        ← 有卡才列；不參與排序
─────────
追加外部資料
搜尋
標籤
更新                ← v3 §7
─────────
最近的標籤／卡片    ← v3 §5，以目前環境為範圍
```

- 環境清單放在首頁下面、追加外部資料上面：四份工作清單（§3）空出來的位置。
- **清單只拿來切換。** 每一項連到那個環境的首頁，目前所在的那一個用 U32 的 selected 底色標起來。新增、排序、改名都在面板裡，不佔清單的位置。
- **先後**：在面板裡排過的照 `envs.yml`；其餘的接在後面，依最近一張卡的建立時間，還沒有卡的排最後、依名稱。沒排過序的語料庫全部照後面這條。
- 首頁、追加外部資料、搜尋、標籤都指向目前的環境；「更新」的表單帶著目前的環境，結果頁留在原地。

**環境面板**：「環境」標題右邊的齒輪打開，畫面中央的一塊浮層，外觀跟右下的隨手記同一套。

```
┌ 環境 ───────────────── ✕ ┐
│ ⠿ 寫作                ✎ │   ← 每一列：把手、名稱、改名
│ ⠿ 學習與記憶          ✎ │
│ ⠿ 繪圖                ✎ │
│ ──────────────────────── │
│ [新的環境名稱    ]  建立 │
└──────────────────────────┘
```

- **瀏覽器內建的 popover**（`popovertarget`）：不用 JS 就打得開，Esc 或點外面就關。元素放在側欄外面，窄螢幕上側欄收起來時它不會跟著不見。側欄拉開時按 Esc，第一下只關面板，第二下才收側欄（`app.js`）。
- **每個環境都能改名**，不再只限目前所在的那一個：每一列都標著名字，不會改錯。改名與新增是一般的表單，沒有 JS 也能用。
- **（無環境）不在面板裡**：它不能改名，也不參與排序。
- **拖曳排序**（`public/js/envs.js`）：拿著把手拖到別的位置，放開就生效。
  - 用 Pointer Events，不用 HTML 的 drag and drop：後者在觸控螢幕上不會觸發。滑鼠、觸控、觸控筆是同一套；把手設 `touch-action: none`，在 iPad 上拖的是那一列，不是捲動畫面。
  - 拿著的那一列跟著指標走，越過鄰居的一半就跟它換位置。移動的是鄰居，不是拿著的那一列：被移動的元素會丟掉 pointer capture 與焦點。
  - 把手也吃上下鍵，鍵盤一樣排得動，焦點留在同一列。
  - 停手 0.4 秒才送出整份順序（連按幾次上下鍵只送一次、只有一個 commit），一次只送一個。沒存成功就退回伺服器那一份，面板裡說一聲。側欄的清單跟著同一份順序重排，不必重新載入。
  - 沒有 JS 時把手不畫（留著位置，名稱才對得齊）；只有一個環境時也不畫。
- **`POST /envs/order`**：送來整份順序，回寫進去的那一份。對不到資料夾的名字（另一個分頁剛改了名）略過；沒送到的環境（另一個分頁剛建的）照它們現在在側欄的先後接在後面。寫進去的是排完之後側欄上的每一個環境。跟改名走同一把寫入鎖，因為改名也會改寫這個檔。

**`envs.yml`**（`store/envorder.ts`）：

```yaml
# 側欄裡環境的順序。在環境面板裡拖曳時由 Skynote 整個改寫。
# 沒列到的環境接在後面；資料夾已經不在的名字略過。
order:
  - "寫作"
  - "學習與記憶"
  - "繪圖"
```

- 跟 `tags.yml` 並排，但這一個由網頁寫入。也可以手改，只是下一次拖曳會整個重寫，註解留不下來。
- 逐行解析，跟 `tags.yml` 同一支（`store/yamllist.ts`），不引 YAML 套件。名字一律加雙引號：環境名稱不能含 `"` 與 `\`，引號裡不必跳脫；「 #」、開頭的 `-` 這些在 YAML 裡另有意思的寫法也不會被誤讀。共用的解析因此也認得引號裡的 `#` 不是註解。
- 只記順序，不是環境的清單：檔案壞掉、不存在，就是還沒排過；手改出對不到資料夾的名字也不會壞事。
- **git**：排序一個 commit，訊息是 `env order`，只有這個檔；內容沒變就不 commit。它跟卡片一樣是本程式寫的，所以開機與「更新」之前「補上只有檔案、沒有 commit 的東西」那一步也補它——留在工作區沒 commit 的話，取回時的 rebase 會拒絕執行。
- **App Engine**：只經 git 保存，不進 bucket（§2.10）。

### 2.9 索引

- `cards` 表加一欄 `env TEXT NOT NULL DEFAULT ''`，空字串是（無環境），並建 `(env, created)` 的索引。`SCHEMA_VERSION` 5 → 6；照既有慣例，版本不合就整個重建，不寫遷移。
- 重建時掃描 `cards/` 與其下一層資料夾（`listCardFiles`）。
- **同一個 ID 出現在兩個資料夾**（例如在別處搬檔時兩邊各留一份）：先到的那份進索引（（無環境）先，其餘依環境名稱，跟 `findCard` 同一個順序），其餘列進報告的「讀不出來的檔案」，不中斷重建。
- **環境底下的資料夾**：列進同一份報告，裡面的卡沒有進索引。
- **以環境為界的查詢**：`listCards`、`tagCounts`、`search`（可以不帶環境）、側欄下半的最近卡片。`envStats` 給側欄裡沒排過的那一段排順序，也決定 `/` 通往哪個環境。
- **維持全域的查詢**：`getCard`、`typeOf`、`isCited`、`outLinks`、`backLinks`、`linkTree`、`pickerSearch`（目前環境排前）。連結的兩頭各自帶著 `env`，上下游串才標得出別的環境。

### 2.10 App Engine：bucket 與對帳

- **物件名稱**就是路徑：`cards/{id}.md`、`cards/{環境}/{id}.md`。`CARD_OBJECT` 收 `cards/` 底下一層的環境；更深的、以 `.` 開頭的資料夾都不算卡片。
- **寫入、修改、勾選、刪除**動的是卡片所在環境的那個物件；git 的路徑跟著它。
- **對帳**（`store/reconcile.ts`）讀本機時含各環境的資料夾。同一張卡換了資料夾（在別處搬進環境、網頁上改名），在對帳裡是「新名字只有本機有」加上「舊名字只有 bucket 有」：前者上傳，後者要刪掉。為此對帳的表多兩條、改一處：
  - **只有 bucket 有、同一張卡以相同的內容在本機的另一個資料夾**：刪掉，那是搬走留下的舊名字。不論那個物件的標記是什麼。
  - **只有 bucket 有、內容在 git 歷史裡**：以 git 為準（刪掉），而且要先於「base 等於本機那份」那一條問。網頁上建立、之後沒再改過的卡，base 是 none，跟「本機沒有」記成的雜湊相同；原本的順序會把一張推上去之後在別處被搬走（或刪掉）的卡當成還沒推上去的新卡取回來，搬進環境之後（無環境）就永遠清不空。這一條也修正了 v3.1 之前就有的行為：在別處刪掉一張網頁上建立的卡，以前會被取回來。
  - **換資料夾不算進「一次刪太多」。** 刪掉的物件，ID 還在本機的另一個名字底下，卡片就沒有少。把整個語料庫搬進環境時，要刪的會是全部，不排除的話那個保護會整批擋下來。
  - **先寫、後刪。** 新名字全部傳上去之後才刪舊名字，中途失敗也不會兩邊都沒有。
- **`envs.yml` 不進 bucket**，只經 git 保存（開機時 clone、「更新」時取回）。bucket 保護的是卡片；為了排序讓對帳多處理一種物件，不值得。代價：push 失敗又剛好換了機器，最後一次排序回到上一版，卡片不受影響。

### 2.11 推翻 v2 G 節的裁決

v2 G 節「**否決增加領域分類維度**：跨領域思維碰撞是卡片盒的核心價值，硬性領域切割會扼殺意外的關聯發現」，由本節推翻。

理由：實際使用下來，跨分野雜訊的代價高於意外關聯的收益。原裁決要保護的東西由跨環境連結保留——卡片仍然可以指向任何環境的任何一張卡，搜尋也可以切到所有環境。

## 4. 版面與配色

### 4.1 側欄常駐的寬度、窄版內容欄置中

使用者常用的畫面包含 1080×1920 的直立螢幕。原本側欄 60rem（960px）以上才常駐；那個寬度在系統縮放之下（125% 剩 864px）落在線下，側欄收起來，內容欄又靠左，右邊空一大片。

- **側欄 45rem（720px）起常駐。** 扣掉側欄還有 480px；內容欄的左右留白在 45–60rem 之間降一階（`--sp-5`），60rem 起回到 `--content-gap`。內容欄在側欄右邊那塊區域裡置中。
- **有來源面板的分欄頁維持 60rem**：從卡片頁 `+` 進來的表單 50rem 起左右分欄（iPad 直放 820px 也算左右分，既有的決議），側欄要是在 45–60rem 之間常駐，兩欄就各剩不到 300px。用 `body:has(.split)` 分開兩條線。
- **窄版（側欄收起來）內容欄置中**，不再靠左。

### 4.2 型別色

### 4.3 換頁不閃：CSS 嵌進頁面、電腦不載網路字型

使用者在電腦上透過 Ferdium 使用，點任何連結都會閃一下。

**原因**：Ferdium 把網頁包在 Electron 的 `<webview>` 裡，那裡沒有一般分頁「舊畫面留到新頁畫好為止」的保護（paint holding）。新頁一接手，舊畫面就沒了；新頁畫出第一格之前，看到的是外殼自己的底色——Ferdium 開著深色模式，就是一塊黑。新頁要等 CSS 才畫得出來，每換一頁六支 CSS 都要回伺服器驗證一次；隔著 IAP，那一來一回就是看得見的一閃。

**第一版做錯的地方**：先做的是讓 CSS 與 JS 長期快取（網址帶版本、回 `immutable`）。本機量起來有效，上線之後照樣閃。正式環境的請求記錄裡，手機與 Ferdium 每換一頁都對每一支 CSS 與 JS 送出條件請求、拿到 304；Ferdium 快取裡存的回應標頭是 `cache-control: no-cache, must-revalidate`、`pragma: no-cache`、`expires: Fri, 01 Jan 1990`——**IAP 把每一個回應的快取標頭都蓋掉了**，程式給什麼都沒用。本機沒有 IAP，所以測不出來。

**驗證**：用跟使用者的 Ferdium（7.2.3）同版的 Electron 43 搭一個深色外框加 `<webview>` 的替身，點連結時逐格錄下外框視窗、量內容區的平均亮度（頁面約 245，外框底色 30）。本機前面加一層代理，延遲 80ms、把快取標頭換成 IAP 那一套：

| 做法 | 出現黑格 |
|---|---|
| CSS 另外請求（原本，以及第一版的長期快取） | 6 / 6，每次 50–110ms |
| 加上 View Transitions（`@view-transition { navigation: auto; }`） | 8 / 8：跨頁轉場同樣靠 paint holding，在 webview 裡沒用，不採用 |
| **CSS 嵌進頁面（本節的做法）** | **0 / 10** |
| CSS 與 JS 都嵌進頁面 | 0 / 10：JS 是 defer 的，不擋第一格，不必嵌 |

**做法**（`src/web/assets.ts`）：

- `layout.eta` 的六支 CSS 改成 `<style><%~ it.inlineCss('/static/css/…') %></style>`，順序不變（`tokens.css` 在最前面，`@layer` 的順序才宣告得到）。去掉註解：約 33KB，壓縮後約 6KB，每一頁多帶這些。依修改時間快取，開發時改完存檔，下一頁就是新的。
- `/static/css/*.css` 照樣拿得到，只是頁面不再用它們。
- **JS 照舊另外載入**，網址帶著內容 SHA-256 的前 10 碼（`it.asset(...)`）。版本對得上才回 `public, max-age=31536000, immutable`，不帶或對不上照舊 `no-cache`（部署時舊機器接到新頁面發出的請求，不會把舊內容記在新網址底下一年）。在 IAP 後面這個標頭會被蓋掉，但 JS 本來就不擋第一格；長期快取在沒有 IAP 的部署（本機、VM）才有效。
- **網路字型只給觸控裝置**（`media="(pointer: coarse)"`）。CSS 嵌進頁面上線之後，Ferdium 照樣會閃，只是少一點。正式環境的記錄確認 Ferdium 已經不再請求 CSS，所以原因在別處。替身改成每輪點不同的卡片（實際使用時，大部分的頁面是第一次打開），並接上 Ferdium 真正的預載腳本（`app.asar/webview/recipe.js`）。量到的空檔是這樣：HTML 收完到第一次繪製之間沒有任何被擋住的請求，但要等 50–120ms，超過約 90ms 就看得到黑格。這段時間主執行緒在忙。Noto Sans TC 依字元範圍切成上百個字檔，一頁用到十幾個；字檔就算在快取裡，每換一頁也要在畫第一格之前重新解碼。Ferdium 的預載腳本影響不大。
  - Windows 11 本身裝著 Noto Sans TC（`C:\Windows\Fonts\NotoSansTC-VF.ttf`，可變字重），而 `tokens.css` 的字體堆疊本來就排它第一個。電腦上不載網路字型，畫出來的是同一套字：截圖逐像素比對，差異約 1%，都在字的反鋸齒邊緣。
  - 手機（Android 的 Chrome）一般分頁有 paint holding，字型的那段空檔看不見，所以照舊載網路字型，字形完全不變。`media` 對不上的樣式表不擋繪製，裡面的 `@font-face` 也不會生效。
  - 沒裝 Noto Sans TC 的電腦，會換成堆疊裡的下一個（微軟正黑體）。

| 做法（替身，每輪點不同的卡，含 Ferdium 預載腳本） | 出現黑格 | HTML 開始回來到第一次繪製（中位數） |
|---|---|---|
| CSS 嵌進頁面，網路字型照載（第一次上線的版本） | 5 / 12 | 72ms |
| **加上網路字型只給觸控裝置（本節的做法）** | **1 / 24** | **36–39ms** |

  剩下那一次是開啟後的第一次換頁。
- `test/v3.1.test.ts` 守著這幾件事：
  - CSS 嵌在頁面裡，順序與內容對得上原檔。
  - JS 帶著對的版本。
  - 模板裡唯一的樣式表是 Google Fonts，而且帶著 `media="(pointer: coarse)"`。
  - JS 都經過 `it.asset`。

  在 webview 裡，每一個擋住第一格的請求、每一份要解碼的網路字型都是一閃。
- 嵌進頁面之後，class 名稱也會出現在 `<head>` 的 CSS 裡。測試在整頁 HTML 裡找 class 時要找標記的寫法（`class="youarehere"`），不能只找名字。

### 4.4 換頁不換文件（nav.js）

§4.3 上線之後，使用者回報閃得快很多，但還是會閃，連點同一個連結也會。同一個 Ferdium 裡的其他服務（Discord、Claude、Gemini、Twitter、Google Drive）都不會閃。

**原因**：那些服務都是單頁應用，點連結不換文件，舊畫面留在原地，直到新內容換上。Skynote 每點一次都換一份文件，而 webview 沒有 paint holding，新文件畫出第一格之前一定有一段空檔。§4.3 把空檔縮到幾十毫秒；電腦一忙，空檔就又看得見了。

**驗證**：替身的作法與 §4.3 相同，並且每輪點不同的卡片。為了讓量測抓得到舊版的閃，用 CDP 把頁面的 CPU 調慢 4 倍，當作比較忙的電腦。在一般速度下，替身的截圖已經抓不到 §4.3 版本的黑格，但使用者看得到，所以那一組量測不能用來判斷修好了沒有。

| 版本（CPU 調慢 4 倍） | 每次點不同的卡 | 連點同一張 |
|---|---|---|
| §4.3（換文件） | 6 / 10 出現黑格 | 8 / 10 |
| **本節（換 body）** | **0 / 10** | **0 / 10** |

這不推翻 MVP 規格「server-side render，不要 SPA」的裁決。頁面照樣由伺服器整頁渲染，前端不組畫面、也沒有路由表；沒有 `nav.js` 時照常運作。改的只是拿到下一頁之後怎麼換上去。

**做法**（`public/js/nav.js`，放在 `layout.eta` 的 `<head>`，`defer`）：

- 站內的連結、GET 表單、POST 表單改用 `fetch` 取回下一頁。接著用 `DOMParser` 解析，換掉 `<body>` 與標題，`pushState` 寫入網址，再依序重新執行新 body 裡的腳本。這幾步在同一個工作裡做完，所以中間不會畫出任何一格；下一格就是新頁面，而且腳本已經跑過。
- 腳本的內容依網址（帶著版本）記在記憶體裡。第一次載入後，在空閒時預先取回，換頁時就不必等下載。
- 頁面的腳本不必改寫：
  - 綁在 body 內元素上的監聽，跟著舊 body 一起丟掉。
  - 綁在 `document`、`window` 等不會換掉的對象上的監聽，在那些腳本執行的期間記下來，換頁前拆掉。只記這段期間掛上的，所以 Ferdium 之類的外殼自己掛的不會被拆掉。
  - 拆之前先送一次 `pagehide`，讓 `draft.js` 把等待中的字存起來，順序跟瀏覽器離開頁面時一樣。
- 因此 head 裡只能有 `nav.js` 這一支外部腳本，它排在所有腳本前面（defer 腳本照文件順序執行，它才記得到其他腳本掛的監聽）。其他腳本都放在 body，換頁時會重新跑。
- 以下情況退回一般的換頁：
  - 回來的不是 HTML。
  - 不是同一版的 `nav.js`。
  - 那一頁的樣式不在現在的 `<head>` 裡（多半是剛部署過）。
  - 網路錯誤。IAP 登入過期時，`fetch` 跟著導向 Google 的網域會失敗，於是改成一般換頁，照常去登入。
- POST 不重送：
  - 已經有回應，就去它導向的網址。
  - 還沒有回應，就重新載入原本那一頁；打的字還在草稿裡。
  - 送出中再按一次會被忽略。送出後又點了別的連結，結果收下但不畫。
- POST 沒有導向時（驗證失敗退回表單、「更新」的結果），網址留在原本的頁面，不另開一筆歷史。換到同一個網址時，也是取代現在那一筆，跟瀏覽器自己的做法一樣。
- 上一頁、下一頁由 `popstate` 重新取回那一頁。捲動位置記在 `history.state` 裡，等新內容換上後再捲回去（`scrollRestoration = 'manual'`）。瀏覽器自己的還原會在新內容還沒到時捲動舊畫面，那一下跳動本身就是一閃。
- 一份文件只在第一次載入時處理 `autofocus`，所以換上新內容後，由 `nav.js` 自己把焦點放到看得見的 `[autofocus]`，例如搜尋頁的輸入框。
- 等超過 0.4 秒時，`<html>` 標上 `aria-busy`：頂端出現一條靜止的細線，游標變成忙碌。因為沒有換文件，瀏覽器自己的讀取進度不會出現；少了它，網路慢的時候按下去像是沒有反應。0.4 秒以內的換頁不出現這條線，否則它一閃而過，本身就是一閃。
- `editform.js` 存好、刪好之後的換頁改走 `window.skynoteNav.visit`。
- 模板裡不能有 `<noscript>`，也不能把事件寫在屬性上：`DOMParser` 不執行腳本，換上的 `<noscript>` 會被當成一般元素畫出來。

**測試**：`test/v3.1.test.ts` 的 §4.4 守著上面幾條模板規則，以及 `editform.js` 不直接換文件。瀏覽器裡的行為用 Electron 替身逐項驗證過，包括：

- 換頁後是同一份文件，日期與引用串的腳本也重新跑過。
- 上一頁、下一頁，以及捲動位置。
- 來回八次之後，`document` 與 `window` 上的監聽數不變。
- 隨手記送出後導向，`?d=` 把草稿清掉。
- 搜尋的 GET 表單與 autofocus。
- 編輯存檔後回到卡片頁。
- 環境排序照樣存進伺服器。
- 過程中沒有任何例外；回應不是 HTML，以及 IAP 登入過期時，都會退回一般換頁。

## 8. 核心裁決紀錄（G 節補充）

1. **推翻「否決增加領域分類維度」**（§2.11）。跨分野雜訊的實際代價高於意外關聯的收益，後者由跨環境連結與「所有環境」的搜尋保留。
2. **環境不進規則層，各環境規則一致。** 個別環境有自己的規則，會回到規則互不一致、操作不自由的問題。
3. **環境以資料夾表達，不寫進 frontmatter。** 既有卡片不必改寫，日後搬動卡片也不必改動內容。
4. **否決以標籤作為分隔機制。** 標籤與空間混用會讓兩者都變得雜亂。
5. **（無環境）是過渡的狀態，不是一個環境。** 搬空了就不列、它的頁面導向最近寫過的環境、不能改名。
6. **側欄的四份工作清單全部移除，路由一起拿掉**（§3）。沒有入口的頁面只會腐爛。
7. **環境可以改名，改的是資料夾名稱**（§2.7）。卡片的內容與 ID 不變；改名是「一張卡一個 commit」唯一的例外。
8. **換資料夾不是刪除**（§2.10）。對帳認得搬走留下的舊名字，「一次刪太多」只數真的少掉的卡；先寫新名字、後刪舊名字。
9. **git 照卡片的 ID 去 stage，不照路徑**（§2.7）。排隊的 commit 輪到時，卡片可能已經換了資料夾；推上去的每一個版本裡，卡片都要在某個地方。
10. **「推上去了沒有」只問剛 clone 下來的歷史**（§2.7）。本機的 git 歷史含還沒推上去的 commit，拿它判斷會在換機器之後把卡當成舊的刪掉。
11. **分欄頁的側欄晚一點常駐**（§4.1）。側欄常駐的線為了 1080 寬的直立螢幕降到 45rem，但不能為此犧牲 iPad 直放的左右分欄。
12. **環境的先後由使用者排，記在語料庫裡**（§2.8）。每台裝置看到同一個順序。`envs.yml` 只記先後，有哪些環境仍由資料夾決定；它只經 git 保存、不進 bucket——為了排序讓對帳多處理一種物件，不值得。
13. **`/` 通往最近寫過的環境，不是排第一的**（§2.3）。排序是先後，不是「預設的環境」。
14. **拖曳用 Pointer Events**（§2.8）。HTML 的 drag and drop 在觸控螢幕上不會觸發，iPad 上就排不了。
15. **CSS 嵌進頁面，不靠快取**（§4.3）。包在 webview 裡的頁面沒有 paint holding，換頁時擋住第一格的每一個請求都是看得見的空檔；而 IAP 會把快取標頭全部蓋成 `no-cache`，靠快取省掉那個請求在正式環境行不通。量效果要在 IAP 那一套標頭底下量，本機的結果不算數。電腦上也不載網路字型，因為解碼十幾個中文字檔的時間同樣會落在第一格之前；用的是 Windows 內建的同一套 Noto Sans TC。量的時候每輪要點不同的頁面，並接上 Ferdium 的預載腳本：來回點同兩頁，字檔已經解碼好了，量不出這件事。
16. **換頁不換文件**（§4.4）。webview 裡只要換文件，空檔就在；縮短它只是讓閃得比較快。站內換頁改成 fetch 下一頁、換掉 body，跟放進 Ferdium 不閃的那些單頁應用同一個道理。頁面的腳本維持「載入時跑一次」，由 nav.js 負責在換頁時拆掉舊的監聽、重新跑新的腳本；接不住的情況一律退回一般換頁。量效果時要讓電腦忙一點（CPU 調慢），平常的速度下替身量不出使用者看得到的那一閃。
