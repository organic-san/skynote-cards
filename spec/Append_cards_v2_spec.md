# Skynote — v2 規格（實作基準版）

> 專案名 **Skynote**；技術層識別（套件名、systemd unit、語料庫路徑）一律沿用 **append-cards**，介面上顯示 Skynote。
>
> 本文件為系統實作的設計規格與意圖說明書。記錄系統現行的核心架構、資料模型、因果約束、介面決策，以及各項設計「為什麼這樣做、為什麼不那樣做」的意圖性理由。
>
> **編號規則**：
> - **R 開頭**：domain 層硬性規則，編號為唯一識別碼，一經指派永不重編。
> - **G 節**：記錄被明確否決或裁決的邊界做法，避免日後重新繞回死胡同。

## A. 型別系統

### A.1 定義與責任

型別的判準是**這張卡錯的時候該怎麼修**。不是篇幅長短，不是隨興程度，也不是載體形式。

| type | UI 標籤 | 對誰負責 | 錯的方式 | 修法 |
|---|---|---|---|---|
| `original` | 資料 | 不是我寫的 | 我抄錯了 / 存錯了 | 重存一份更正的資料卡 |
| `restatement` | 重述 | 對原文負責 | 我誤讀了 | 重讀原文，發新的重述 `updates` |
| `thinking` | 思考 | 對世界負責 | 命題為假 | 換一個主張，發新的 thinking `updates` |
| `fleeting` | 碎片 | 尚未決定 | —— | 完整化成 thinking，或就讓它留著 |

- **`original`（資料）**：一手文獻、外部文章、對話切片或書籍章節。UI 標籤定名為「資料」（與側欄動作「追加外部資料」對齊）。它是所有論證與重述的錨點，錯誤來自記錄失真。
- **`restatement`（重述）**：用自己的話重寫原文。它的唯一責任是忠實於原文，因此只要發現誤讀，修法就是換一張新的重述。
- **`thinking`（思考）**：自己的論點、主張、推論或反駁。它的責任面向現實世界與邏輯真實性，錯的時候代表原本的思維模型不成立。
- **`fleeting`（碎片）**：隨手記下的一句話、閃過的靈感或衝動。它存在的理由是**一句隨口的話需要一個不必負責的地方**。若強行要求它歸入重述或思考，會讓「我想錯了」與「我只是隨手記」混在一起。

碎片唯一預期的生命週期是**被完整化**：發一張 `thinking`，用 `updates` 指向它。那條鏈記錄了「一個隨口的想法在哪一天演化成一個嚴肅的主張」，是知識系統中最具價值的演化軌跡。

### A.2 型別的硬性約束

**R1. `restatement` 必須至少有一條 `about` 指向 `original`。**
沒有原文可對照的東西不是重述。這條規則直接消除「參照對象是外部世界、卻自稱重述」的卡片——那種卡片依定義是 `thinking` 或 `fleeting`。

**R2. `fleeting` 不得有任何連結。**
一旦開始建立關聯，做的就是 `thinking` 的工作。這條規則讓碎片的建立成本真正降到「一個輸入框、直接打字、送出」，杜絕任何決策負擔。

**R3. 每一型只能使用自己被允許的 rel（見 A.3），且目標型別必須符合矩陣。**
硬性規則，不是警告：**有方向的規則可以之後放寬，沒有約束的欄位只會發散。** 矩陣保證每條連結具備明確的知識拓撲語義。

**R4. 規則改動不追溯既有卡片。**
既有卡片不可變，任何收緊或放寬都只作用於此後建立的卡片。重建索引時，違反現行規則的舊卡片列入警告清單，不視為阻斷性錯誤。但反芻期內的修改視同建立的一部分，仍須通過當下的現行規則。

### A.3 關係（rel）詞彙表與方向性

所有連結皆有方向，由新卡片（來源）指向較早建立的舊卡片（目標），保證整體結構為有向無環圖（DAG）。介面上依視角以不同稱呼呈現：

| 來源 type | rel | 目標 type | 來源端視角（上游） | 目標端視角（下游） | 核心意圖 |
|---|---|---|---|---|---|
| `original` | `part-of` | `original` | 節錄自 | 包含於 | 長文文獻切成小篇幅摘錄，指回母卡 |
| `original` | `updates` | `original` | 更新自 | 更新至 | 換上更完整、更正確的文本副本 |
| `restatement` | `about` | `original` | 論及（重述） | 被重述 | **必填，至少一條**（R1），錨定原文 |
| `restatement` | `updates` | `restatement` | 更新自 | 更新至 | 修正先前的誤讀 |
| `thinking` | `about` | `original` / `restatement` | 論及 | 被論述 | 這則思考以該份材料為討論主題 |
| `thinking` | `supports` | `original` / `restatement` / `thinking` | 支撐 | 被支撐 | 這是我的論點依據或脈絡延伸 |
| `thinking` | `contradicts` | `thinking` / `restatement` | 牴觸 | 牴觸 | 兩者不相容，對稱並立，尚未裁決 |
| `thinking` | `refutes` | `thinking` / `fleeting` | 反駁 | 被反駁 | 主張原卡為假、推翻其論點或直覺 |
| `thinking` | `updates` | `thinking` / `fleeting` | 更新自 | 更新至 | 取代舊主張，或完整化碎片 |
| `thinking` | `related` | 任意 | 關聯自 | 關聯出 | 關係尚未定型，但確認脈絡相通 |
| `fleeting` | —— | —— | —— | —— | 不得有任何連結（R2） |

- **`supports` 排除 `fleeting`**：隨口的一句話不能拿來當作嚴謹論證的依據。這一刀同時讓 `supports` 與 `related` 在結構上產生本質區別，避免選項淪為模糊的文字遊戲。
- **`related` 只開放給 `thinking`**：它是唯一弱語義的 rel，若全面開放會成為逃避定義關係的逃生口，破壞詞彙表的約束價值。

### A.4 W1 警告的撤回意圖

在初期規範中曾考慮設置非阻斷警告「W1：帶有 `refutes` 或 `updates` 卻未引用任何材料」。
**實際實作中已將 W1 徹底撤回**。原因：
1. `supports` 矩陣收窄後，舉證責任已透過關係詞自然引導；
2. 非阻斷性的 UI 警告容易淪為無視的視覺雜訊，或造成不必要的寫作焦慮；
3. 一則批判性思考是否「足夠有據」，應交由反芻期內的思維迭代與後續引用決定，而非由伺服器做半吊子的道德勸說。

### A.5 frontmatter 與欄位設計

共通欄位（四型皆有，序列化時一律寫出，未使用的填 `null`，保持語料庫長相整齊）：
`id` `type` `created` `title` `tags` `url` `provenance` `revised` `links` `source_author` `source_date`

```yaml
# original
url: "https://..."                                   # 選填。一手材料（書籍、手稿）亦可無 url
provenance: default | translated | AI-summarized     # 預設 default（default 在檢視時不顯示）
source_author: "Herbert A. Simon"                    # 選填，自由字串
source_date: "1962"                                  # 選填，原始發表年份，不強制日期格式

# restatement / thinking
# url 與 provenance 必須為 null。source_* 不適用。

# fleeting
# 整句話存在 title，body 為空字串。
# url / provenance / source_* 皆為 null。
```

- **`fleeting` 文字存放於 `title` 的意圖**：系統中的全文檢索、標題索引、分頁標籤、引用串全部以 `title` 為核心。將碎片文字存入 `title`，既有資料模型與索引架構完全不需變更；而在介面上**完全隱藏這個實作細節**：碎片表單只有一個大文字框，不標 title 也不標 body；完整化成思考時，該文字再自動帶入新卡的 `body`。
- **標籤（`tags`）嚴格空白分隔、禁止逗號**：
  標籤輸入僅支援以空白分隔（相容半形與全形空白）。**明確禁止逗號（`,`、`，`）**：若允許逗號與空白並存，輸入時易產生 `世界觀, 構想` 與 `世界觀 構想` 的分歧黏著；卡片一旦定案不可修改，錯誤標籤將永久汙染索引。因此在送出檢核時直接報錯退回，防範於未然。

### A.6 外部媒體內嵌原則

為兼顧閱讀完整性與自主權，外部 URL 僅在卡片檢視頁（`card.eta`）進行極簡且安全的內嵌，不載入任何外部第三方 JavaScript 腳本：
- **YouTube 影片**：
  - 識別形狀：`youtube.com/watch?v=`、`youtu.be/`、`youtube.com/shorts/`、`embed/`、`live/`。
  - 轉換位址：一律使用隱私增強網域 `https://www.youtube-nocookie.com/embed/{id}`，並保留時間錨點 `?start={seconds}`。
  - **安全性與相容性防護**：`<iframe>` 標籤必須設定 `referrerpolicy="strict-origin-when-cross-origin"`（**嚴禁設為 `no-referrer`**，否則 YouTube 伺服器因無法核實來源 Origin 會觸發 **Error 153 視訊播放器設定錯誤**）；同時具備 `allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share"` 與 `allowfullscreen`。
- **圖片與 PDF**：
  - 直接圖片副檔名（`.png`、`.jpg`、`.webp`、`.svg` 等）使用 `<img>` 載入，設定 `referrerpolicy="no-referrer"`。
  - `.pdf` 副檔名使用原生 `<iframe>` 載入，設定 `referrerpolicy="no-referrer"`。
- **非 HTTPS 與未知站點**：一律不內嵌，降級為純文字外部超連結，杜絕混合內容與外部追蹤。

### A.7 型別呈現與色彩意圖

型別不靠花俏徽章，而是透過**雙重錨定**：
1. **色點（Color Dot）**：負責瞬間視覺掃描；
2. **無色型別名**：負責明確語意確認，不單獨依賴色彩傳遞資訊。

| type | UI 標籤 | 色點樣式 | 視覺意圖 |
|---|---|---|---|
| `original` | 資料 | 實心藍 `#4A7FB5` | 外在客觀材料，沉穩冷靜 |
| `restatement` | 重述 | 實心綠 `#4F9D69` | 消化轉譯，生命力與過渡 |
| `thinking` | 思考 | 實心琥珀 `#D99A2B` | 智慧火花與主動論述，高聚焦度 |
| `fleeting` | 碎片 | 空心灰環 `#9CA3AF`（透明底） | **唯一的形狀例外**：空心表達「尚未定案、容器待填」的暫時狀態 |

四色在 OKLCH 色彩空間上校正亮度與彩度（L≈0.62、C≈0.11），達成等重平衡，避免思考卡過度搶眼。

## B. 側邊欄：從儲存分類改為工作狀態

側邊欄不是檔案夾目錄，而是回答**我接下來要做什麼**的行動清單。

```
Skynote          ← 純文字站名，不可點擊
首頁             ← 第一列可點項目，手指最自然的落點，回首頁時間軸
待思考           ← 工作狀態 1
初步想法         ← 工作狀態 2
雜筆             ← 工作狀態 3（原碎片工作清單，更名以消歧義）
沉澱             ← 工作狀態 4（反芻期內尚可編輯的卡片）
─────────
追加外部資料     ← 建立 original 的入口（與工具同格式）
標籤             ← 標籤索引
搜尋             ← 中文全文檢索
─────────
卡片索引         ← 下半工具區，依時間列出最近卡片（色點+標題，供連結參照）
```

### B.1 四份清單的共通判準：「有沒有被接住」

三份待處理清單問的是同一個因果問題：**這張卡有沒有被後續的思維接住**。
- **待思考**（`original` 且無入向連結）：收集進來的文獻尚未被重述、節錄或論述。這是系統主動維持「有題目可想」的源泉。
- **初步想法**（`thinking` 且無任何進出連結）：懸空的主張，既沒有材料支撐，也尚未被拿來應用。
- **雜筆**（`fleeting` 且無入向連結）：尚未被完整化或反駁的隨手記。
  > **「雜筆」命名意圖**：避免與首頁型別篩選的「碎片」混淆。「碎片」代表所有 fleeting 卡片；側欄「雜筆」則只代表「尚未被處理的 fleeting 待辦子集」。
- **沉澱**（仍在反芻期且未定案的卡片）：給予大腦二次反芻、調整字句或刪除手滑錯誤的檢視清單。

### B.2 移除計數數字的意圖

清單項目後方**不顯示數量數字**：
這些清單實務上不會、也不需要「歸零」。一個永遠閃爍著「47」或「128」的紅色或灰色數字，只會帶來虛妄的待辦焦慮，將知識累積異化成消耗任務。清單滾動的物理長度本身就是充足的量感反饋。

### B.3 卡片索引的定位

側欄下半部提供「卡片索引」：
- 其定位是**撰寫新卡建立連結時的名稱參照工具**，不是導航分類；
- 標題以「卡片索引」小標清晰標示職責，字級比主選單降一階，顏色採次要中性灰階；
- 每一項目僅以型別色點搭配標題，空間緊湊且安靜。

### B.4 滾動與互動細節

- **整條平滑滾動**：側欄捨棄內部固定分割條，整體採用一致的邊距與整條滾動，頂部保留呼吸空隙，避免頂端出現不自然的斷層空白；
- **手機端避障**：在窄螢幕行動裝置下，當側邊欄展開時，左上角的漢堡按鈕自動隱藏，避免遮擋側欄標題與首頁按鈕。

## C. 建立流程與脈絡繼承

### C.1 核心原則

**建立卡片的入口應該長在它的參照對象上，而不是全域。**

若先點「新增」，再回頭翻找要連向誰，順序本末倒置，也是貼 ID 痛苦的根源。「先閱讀、在閱讀的地方衍生思考」才是自然的認知路徑。

### C.2 全域入口：依動機分開

全域建立只服務「無任何參照的初始卡片」，分為兩種互不干擾的入口：

1. **右下浮動隨手記（時間軸/首頁）**：
   - 包含標題與內文兩個欄位。
   - **不填標題就是碎片（fleeting）**：直接把字倒出來，內文自動轉存入 `title`。
   - **填寫標題就是思考（thinking）**：標題存入 `title`，內文存入 `body`。
   - **「展開成思考」按鈕**：若寫到一半發現思維膨脹，可點擊展開按鈕，將已填寫的草稿帶至完整表單（鎖定 `thinking` 型別，並提供返回按鈕）。
2. **側欄「追加外部資料」**：
   - 用於收納新讀到的一手文獻或網頁，直接開啟 `original` 專屬完整表單。

### C.3 卡片詳細頁的 `+`（FAB）

每張卡片檢視頁右下角的 `+` 按鈕，點擊後依當前卡片型別展開 3～5 顆具名語義動作按鈕（見 A.3）。

#### 全域脈絡自動繼承意圖
在思考網絡中，從某張卡片衍生出的討論，本質上處於相同的思維語境與主題領域之中。
因此，**所有在卡片頁按下 `+` 建立的新卡片，均實施以下自動繼承**：
1. **標籤自動繼承**：
   所有基於原卡片開出的新表單，自動將來源卡片的 `tags` 以空白分隔填入新卡表單的標籤欄位中。使用者可自由增刪，但預設延續語境脈絡。
2. **節錄資料自動繼承**：
   從 `original` 點擊「節錄」（`part-of`）時，新表單除了繼承標籤，還自動帶入母卡的 `url`、`source_author`、`source_date` 與 `provenance`。
3. **碎片文字自動繼承**：
   從 `fleeting` 點擊「完整化」（`updates`）時，碎片原本記錄的那句話會自動填入新思考卡片的 `body` 中，完成草稿到正文的無縫轉移。
4. **唯讀鎖定連結**：
   由 `+` 帶出的來源連結在表單中為**唯讀列**（目標顯示標題，ID 隱蔽，無刪除按鈕，僅可切換相容的 rel），防止手滑誤砍因果鏈。
5. **分欄來源對照面板（Source Pane）**：
   若新卡帶有參照對象，頁面自動分為左右雙欄：左側完整展示原文以供精確對照引用，右側為輸入表單；驗證失敗退回時來源面板持續伴隨。

### C.4 送出後的導向與一鍵返回

卡片送出成功後，系統導向新建立的卡片檢視頁。
頂端標題上方顯示醒目的 **`已從 ⟨來源卡標題⟩ 建立` 一鍵返回按鈕**。
- **意圖**：建立一張衍生卡片通常是為了記錄當下的想法，記錄完畢後的下一步幾乎總是**回到剛才正在閱讀的文章繼續往下讀**。此按鈕讓思維迴圈順暢閉合。
- **例外**：碎片（fleeting）建立後導向首頁，因為碎片隨手記的核心是連續快記，回首頁能讓「連記三句」保持流暢。

## D. 反芻期（Rumination Period）

### D.1 窗口長度

**R5. 卡片自建立起有一段可修改的反芻期，長度由 `EDIT_WINDOW_HOURS` 決定，預設 8 小時。**

人的思維不是打卡鐘。衝動記下的觀點需要經過沉澱、一次散步或一夜睡眠，才能辨識出「哪些詞句不精確、哪些才是核心重點」。8 小時允許在當天工作階段結束前回頭審視與潤飾。

### D.2 定案：被指向就關窗

**R6. 一旦有任何卡片的 `links` 指向這張卡，它立刻定案，不再可改、不再可刪，不論反芻期是否結束。**

這是一條客觀的因果原則：**有人開始依賴你，你就定案了。**
它同時決定了三件事：從待辦清單移出、關閉編輯權限、禁止刪除卡片。
這條規則守護了引用錨點 `#b{n}` 的絕對可信度——只要被引用，來源卡片的段落結構就永遠鎖定，杜絕靜默腐爛。

### D.3 反芻期內的修改約束

| 欄位 | 可否修改 | 意圖與原則 |
|---|---|---|
| `title` `body` `tags` `url` `provenance` `source_*` | 自由增刪改 | 允許文字精煉、補齊出處與修正錯字 |
| `links` | **只能新增，不能刪除或修改**（R7） | 延續 append-only 精神，避免破壞已有驗證的語意結構 |
| `type` `id` `created` | **不可改** | 型別代表錯的時候怎麼修的契約，改型別應發新卡並 updates 舊卡 |

- **R7. 反芻期內 `links` 只增不減**：表單介面上將既有連結呈現為純文字唯讀清單，下方僅提供新增空列。避免因整包表單送出比對失誤導致連結遺失。
- **R8. `fleeting` 在反芻期內不得新增連結**：維持 R2「碎片無連結」的鐵律，避免碎片在編輯期變相轉化為思考。

### D.4 受控刪除

**R9. 反芻期內、且尚未被任何卡片指向的卡片可以刪除。**

這是 R7（連結只增不減）的必要配套：若連結選錯無法撤銷、且整張卡無法刪除，一次手滑將永遠留在語料庫中。
- 刪除操作執行 `git rm {id}.md` 並產生專屬 commit；
- 歷史記錄仍安全保存在 git commit 紀錄中，但活躍語料庫不再受汙染。

### D.5 狀態可見性

卡片頁 meta 列以次要文字標註反芻狀態：`可修改 N 小時` 或 `已定案`（不套用跳動倒數，維持安靜閱讀）。精確的倒數與唯讀連結控制台僅留在編輯頁面（`/c/:id/edit`）。

## E. 閱讀體驗與關聯可視化

### E.1 閱讀順序

版面順序嚴格遵循：**卡片內容主體在前，關聯結構在後**。
```
[一鍵返回來源按鈕（若有）]
標題
meta 列（型別色點、型別名、絕對日期時間、反芻狀態）
內文
[嵌入式媒體：YouTube / 圖片 / PDF]
[外部來源網址 link]
──────────
關聯區塊（上下游軌道）
```
進入頁面時眼睛第一時間落在內容文字，避免被浮動的連結樹干擾閱讀基線。

### E.2 關聯區塊的體感式結構

關聯結構採用縱向空間隱喻：
- **上游（Upstream）置於上方**（`↑ N`）：表示「這張卡從哪裡來、有哪些依據與前置脈絡」；
- **下游（Downstream）置於下方**（`↓ N`）：表示「這張卡推導出什麼、啟發了哪些後續想法」；
- **「你在這裡」置於中央**：作為當前閱讀卡片的錨點，顯示相對時間戳記。

### E.3 一維平鋪軌道（Track）

關聯樹捨棄易產生排版崩潰的深度巢狀 DOM，由伺服器直接攤平成一維視覺順序輸出：
- 縮排由字符線條軌道（`├─`、`└─`）直接表達；
- 超出欄寬之長標題由 CSS 自動以省略號 `…` 截斷，保持每列一行的高緊湊度；
- 預設展開深度為上游 1 層、下游 2 層；
- 當存在隱藏的巢狀節點時，「你在這裡」橫列右側提供「全部展開」按鈕。

### E.4 內文單一換行即換行

Markdown 渲染引擎開啟 `breaks: true`：
- **單一換行就是換行**，刻意偏離 CommonMark 合併空格的預設行為；
- 在瀏覽器文字框寫作時，換行是刻意的語氣頓挫與結構切分；
- 此設定僅影響段落內的軟換行，**完全不影響頂層區塊的劃分**，因而穩固保護了引用錨點 `#b0`、`#b1` 的長期穩定。

## F. 工程架構與實作紀律

系統採用清晰的四層單向依賴分層架構：

```
domain/   業務規則核心（無任何 HTTP、無 SQL 依賴，純資料轉換與驗證）
  types   型別標籤、rel 矩陣、CARD_ACTIONS、驗證邊界
  rules   R1–R9 具名規則驗證函式、反芻期運算（ruminationOf）
  card    Card 資料結構、frontmatter 序列化與反序列化
store/    持久化存取層
  files   cards/ 目錄下的 Markdown 檔案讀寫
  index   SQLite 快取庫：DDL、WAL 配置、FTS5 全文索引、重建
  backup  Git 本地 commit 與遠端異步推送
service/  用例協調層（將 domain 規則與 store 落地串聯）
  cards   卡片建立、修改、刪除與反芻狀態檢查
  lists   待思考、初步想法、雜筆、沉澱清單查詢
web/      介面與傳輸層
  routes  Fastify 路由定義、請求清洗、模板指派
  present View Model 轉換、選單計算、時間戳記格式化
  render  Eta 模板引擎與 Markdown-it 渲染
  views/  .eta 視圖範本
```

### 架構核心紀律
1. **規則具名化**：每一條約束（R1、R2、R3 等）皆為 `src/domain/rules.ts` 中的獨立具名純函式，API 寫入與頁面檢查呼叫同一份函式，杜絕邏輯分歧；
2. **差異集中於表格**：型別矩陣、動作選單、欄位規範集中於資料表（Data Table），不散落於 if/else 判斷叢林；
3. **樣式 Token 紀律**：全站間距、色彩、字級、陰影統一收斂於 `public/css/tokens.css` 的 `@layer tokens`，嚴禁於元件私自寫死魔術數字。

## G. 已裁決與被否決的邊界設計紀錄

本節記錄經實際驗證後明確否決的方案，防止日後無謂重複討論：

- **否決「延伸 / 反駁」產生 fleeting**：可以「從」fleeting 反駁或完整化，但產生的新卡必然具備反向連結，而 R2 規定碎片不得有連結。R2 優先，故衍生動作一律產生 `thinking`。
- **否決 `refutes` 指向 `restatement`**：重述的錯誤類型是「誤讀」，修法是發新卡 `updates` 取代舊重述。對重述提出「反駁」屬於類別混淆。
- **否決逗號作為標籤分隔符號**：全域僅承認半形與全形空白分隔。禁止逗號，防止不可變卡片因輸入法習慣產生髒資料標籤。
- **否決在側欄清單顯示剩餘數量**：知識卡片不以清空待辦為目的，數字只會製造干擾與焦慮。
- **否決正文引用參與定案鎖定**：引用鎖（R6）僅檢查 frontmatter 的結構化 `links`，正文中的 `#b{n}` 連結不納入鎖定計算，避免大幅增加索引複雜度。
- **否決增加領域分類維度**：跨領域思維碰撞是卡片盒的核心價值，硬性領域切割會扼殺意外的關聯發現。
- **否決 YouTube 內嵌使用 `no-referrer`**：YouTube 嵌入播放器需要合法的 Origin 授權標頭，強制 `no-referrer` 會引發 Error 153，故採用 `strict-origin-when-cross-origin`。
