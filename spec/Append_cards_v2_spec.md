## A. 型別系統：三型擴為四型

### A.1 定義

型別的判準是**這張卡錯的時候，該怎麼修**。不是篇幅，不是隨興程度。

| type | UI 標籤 | 對誰負責 | 錯的方式 | 修法 |
|---|---|---|---|---|
| `original` | 原始 | 不是我寫的 | 我抄錯了 / 存錯了 | 重存一份 |
| `restatement` | 重述 | 對原文負責 | 我誤讀了 | 重讀原文，發新的重述 `updates` |
| `thinking` | 思考 | 對世界負責 | 命題為假 | 換一個主張，發新的 thinking `updates` |
| `fleeting` | 碎片 | 尚未決定 | —— | 完整化成 thinking，或就讓它留著 |

`fleeting` 的存在理由：一句隨口的話需要一個不必負責的地方。把它塞進
`restatement` 會讓「我誤讀了」和「我想錯了」混在同一格，而這兩種錯的
修法完全不同。

`fleeting` 唯一預期的生命週期是**被完整化**：發一張 `thinking`，
用 `updates` 指向它。那條 updates 鏈記錄的是「一個隨口的想法在哪一天
變成一個主張」，這是這個系統最有價值的產出之一。

> **型別名稱以本表為準。** 早期草稿寫過 `think`，那是用詞漂移，
> 正式名稱是 `thinking`。既有卡片檔裡已經是 `thinking`，
> 解析器不認得其他寫法，改動會讓既有卡片解析失敗、從系統中消失。

### A.2 型別的硬性約束

這些在**建立時**驗證，失敗即整筆拒絕：

**R1. `restatement` 必須至少有一條 `about` 連結指向 `original`。**
沒有原文可對照的東西不是重述。這條規則直接消除了「參照對象是世界的
restatement」——那種卡片依定義是 `thinking` 或 `fleeting`。

**R2. `fleeting` 不得有任何連結。**
一旦你開始建立關聯，你做的就是 thinking 的工作。這條規則讓 fleeting 的
建立成本真正降到「一個欄位」。

**R3. 每一型只能使用自己被允許的 rel（見 A.3），且目標型別必須符合。**

R3 是硬性規則，不是警告。理由：**有方向的規則可以之後放寬，
沒有約束的欄位只會發散。** A.3 的矩陣預期會隨使用調整，
而 R4 保證調整對既有資料是免費的。

**R4. 驗證只在建立時執行。**
既有卡片不可變，因此規則改動不追溯。重建索引時，違反現行規則的舊卡片
列入報告的**警告清單**，不視為錯誤，不阻斷重建。

### A.3 rel 詞彙表（依來源型別分）

| 來源 type | rel | 目標 type | 說明 |
|---|---|---|---|
| `original` | `part-of` | `original` | 摘錄卡片指向母文件 |
| `original` | `updates` | `original` | 換上更完整或更正確的副本 |
| `restatement` | `about` | `original` | **必填，至少一條** |
| `restatement` | `updates` | `restatement` | 修正誤讀 |
| `thinking` | `about` | `original` / `restatement` | 這則思考在講什麼 |
| `thinking` | `supports` | 任意 | 這是我的依據 |
| `thinking` | `contradicts` | `thinking` / `restatement` | 兩者不相容，尚未裁決 |
| `thinking` | `refutes` | `thinking` / `fleeting` | 推翻。不含 `restatement`，見 F |
| `thinking` | `updates` | `thinking` / `fleeting` | 取代舊主張，或完整化碎片 |
| `thinking` | `related` | 任意 | 關係尚未定型 |
| `fleeting` | —— | —— | 不得有連結（R2） |

`related` 刻意只開放給 `thinking`。它是唯一沒有語義的 rel，
若每一型都能用，它會變成萬用逃生口而讓整個詞彙表失去作用。

**六週後要量的一件事**：`related` 佔全部連結的比例。若仍高於六成，
代表詞彙表沒有在做事，應縮減成實際會用的兩三個。這個數字索引裡就有。

### A.4 frontmatter：依型別的差異

共通欄位（四型皆有，序列化時一律寫出，用不到的填 `null`——
這樣檔案的長相不隨型別分歧）：

`id` `type` `created` `title` `tags` `url` `provenance` `revised` `links`

> 欄位名以現行程式碼為準：是 **`revised`** 不是 `revised_at`。

型別專屬的規則：

```yaml
# original
url: "https://..."      # 選填。沒有網址的一手材料（實體書、手稿）
                        # 同樣是 original，不該被擋在門外。
provenance: default | translated | AI-summarized     # 預設 default
source_author: "Herbert A. Simon"    # 選填，新增欄位
source_date: "1962"                  # 選填，自由字串，不解析

# restatement / thinking
# url 與 provenance 必須為 null。source_author / source_date 不適用。

# fleeting
# 整句話存在 title，body 為空字串。
# url / provenance / source_* 皆為 null。tags 允許但非必要。
```

**`fleeting` 為什麼把文字存在 `title` 而不是 `body`**

`title` 在現行系統裡是列表顯示、連結選擇器搜尋、分頁名稱、引用串標籤
四處唯一的依靠。把 fleeting 的文字放進 `title`，這四處全部自動正確，
而且「title 必填非空」的既有規則不必鬆動——**資料模型完全不動**。

代價是它跟「標題」這個詞的直覺相反。所以**介面上不呈現這個區分**：
建立 fleeting 時只有一個大的文字區塊，跟一般的內文框一樣大，
不標 title 也不標 body。完整化成 thinking 時，這段文字
**填進新卡的 body**，不是 title。

`source_author` 與 `source_date` 是新增的。理由：目前列表上 original
顯示的是內文開頭（「世界 By Yu An Chan — 27 Jul 2019 我的世界觀…」），
零資訊。有了結構化欄位，列表可以顯示「Yu An Chan · 2019」加上引用計數。

### A.5 型別的呈現差異

現在四型長得一樣，所以型別在介面上不存在。修法不是配色，
是**每一型的列表項與詳細頁提供什麼**。

| type | 列表項顯示 |
|---|---|
| `original` | 標題 · 作者 · 原始年份 · **「N 則重述 / M 則引用」**。不顯示內文開頭 |
| `restatement` | 標題 + 內文前兩行 · 它在講哪份 original |
| `thinking` | 標題 + 內文前兩行 · 出向連結數 · 入向連結數 |
| `fleeting` | 整句話（它就是全部內容） · 日期 |

詳細頁的主要動作見 C.3。

## B. 側邊欄：從儲存分類改為工作狀態

現行的「全部 / 標籤 / 碎片」是三個儲存分類，三個畫面都在回答
「我有什麼」。沒有一個畫面在回答「我接下來要做什麼」。

新的結構，每項後面顯示數量：

```
(標題，Skynote) ← 點這個回首頁（即「最近」）
待思考   N     ← 待處理，會自己長出來
碎片     N     ← 待完整化
初步想法 N     ← 沒有依據的主張
─────────
追加外部資料    ← 建立 original 的入口
標籤
搜尋
```

上半是**工作狀態**，三個都是待辦清單。下半是**動作與工具**。
「追加外部資料」跟旁邊兩項的格式不一致——它是動作，另外兩個是去處——
這是刻意的：建立 original 沒有別的自然位置（它沒有參照對象可以掛），
而它又不該跟隨手記共用同一顆按鈕。見 C.2。

原本的「最近」從清單裡拿掉了，因為側欄頂端的標題本來就是回首頁。

**查詢定義**

| 項目 | 查詢 | 意義 |
|---|---|---|
| 待思考 | `type='original'` 且**沒有任何 `about` 指向它** | 存了但還沒讀，或讀了還沒寫 |
| 碎片 | `type='fleeting'` 且沒有任何 `updates` 指向它 | 尚未完整化的隨手記 |
| 初步想法 | `type='thinking'` 且 `link_count = 0` | 目前沒有依據的信念 |
| 最近 | 全部，時間逆序，可依 type / tag 篩選 | |

**「待思考」用 `about` 判定，而不是「沒有任何入向連結」。**
因為摘錄卡會用 `part-of` 指向母卡，若用後者，摘一段就會讓整篇文章
離開清單——但你只是切開它，還沒消化它。而摘錄正是 original 的
主要動作之一，所以這不是邊緣情況。`about` 才代表有人重述或思考了它。

「待思考」是四項裡唯一會**主動增長**的清單——每存一篇文章就多一項。
這是這個系統要用來取代 SNS 時間所必需的東西：打開就有東西等著處理。

現行側邊欄的「碎片」指向 `/orphans`（thinking 且無連結），
那個語義移到「初步想法」，「碎片」改指型別 `fleeting`。
**現行畫面上的標籤已經是錯的**，本次一併修正。

## C. 建立流程

### C.1 核心原則

**建立卡片的入口應該長在它的參照對象上，而不是全域。**

這條是 I3 的直接推論：連結只能指向已存在的卡片，所以任何帶連結的卡片，
你在建立它的時候一定已經在看目標了。「先導航、再建立」是自然順序，
「先建立、再回頭找目標」是把順序倒過來，而那正是目前需要手動貼 ID 的來源。

全域建立入口因此只服務**沒有任何參照的卡片**。

### C.2 全域入口：兩個，不是一個

全域入口只服務**沒有任何參照**的卡片，而那有兩種完全不同的動機，
所以是兩個入口，不是同一顆按鈕底下的選項。

**一、右下浮動按鈕：隨手記**

展開後是**兩個欄位**——標題與內文——加一個送出鍵。型別由標題決定：

| 標題 | 建立的型別 | 文字存到哪 |
|---|---|---|
| 空白 | `fleeting` | 內文欄的文字存進 `title`，`body` 留空（見 A.4） |
| 有填 | `thinking` | 照常，標題進 `title`、內文進 `body` |

沒有型別選單、沒有標籤、沒有連結。**不填標題就是碎片**——
這是這個系統唯一的生死線，憑空記一句話如果需要一次型別決策，
它就輸給 Discord。而「要不要給它一個名字」本來就是你在寫的時候
自然會做的判斷，不是額外的決策。

> 實作要注意：`fleeting` 的欄位對應是反的——使用者填的是「內文」欄，
> 但存進 `title`。理由見 A.4（title 是列表、搜尋、引用串唯一的依靠）。
> 完整化成 thinking 時再把它填回新卡的 `body`。

現行左下的「＋ 建立卡片」與這顆功能重複，**移除左下那個**。

**二、側欄的「追加外部資料」：建立 original**

一篇剛讀到的文章沒有參照對象，所以它也只能從全域進來。
但它跟隨手記是相反的動作——一個是把外面的東西收進來，
一個是把腦袋裡的東西倒出來——共用一顆按鈕會讓兩邊都變鈍。

點進去是完整的 `original` 表單：標題、url（顯眼位置，見 C.4）、
內文、`source_author`、`source_date`、標籤。

### C.3 卡片詳細頁的 `+`

每張卡片的詳細頁右下有一個 `+`，按下去跳出一個小選單。
**選單裡有哪些按鈕，由當前卡片的型別決定**；每個按鈕都預填好新卡片的
型別與那條連結，使用者不需要知道 R1/R3 這些規則存在。

| 當前卡片 | 按鈕 | 建立什麼 | 預填的連結 |
|---|---|---|---|
| `original` | 節錄 | `original` | `part-of` → 本卡 |
| `original` | 重述 | `restatement` | `about` → 本卡（滿足 R1） |
| `restatement` | 延伸 | `thinking` | `supports` → 本卡 |
| `restatement` | 更新 | `restatement` | `updates` → 本卡 |
| `thinking` | 延伸 | `thinking` | `supports` → 本卡 |
| `thinking` | 反駁 | `thinking` | `refutes` → 本卡 |
| `thinking` | 更新 | `thinking` | `updates` → 本卡 |
| `fleeting` | 延伸 | `thinking` | `supports` → 本卡 |
| `fleeting` | 反駁 | `thinking` | `refutes` → 本卡 |
| `fleeting` | 完整化 | `thinking` | `updates` → 本卡，**內文預填本卡的文字** |

- 「節錄」的標題自動取選取文字前 40 字，可改。
- 「更新」與「完整化」機制相同（`updates` → 本卡），分兩個名字是因為
  語義不同：更新是「換一個更好的版本」，完整化是「把隨口的話變成主張」。
  `fleeting` 只有完整化，沒有更新。
- `restatement` 沒有「反駁」——那是 `updates` 的責任，理由見 F。
- `original` 的詳細頁維持現有的分割視窗（左讀右寫），
  「引用選取的段落」按鈕保留在來源面板上，與這個 `+` 選單並存。

### C.4 表單本身

- 連結欄的標題搜尋已完成，維持。
- 型別選擇維持在表單最前面，但**由入口決定預設值**，
  多數情況使用者不需要碰它。
- `url` 對 `original` 是主要欄位，**從收合區移出來**放到顯眼的位置；
  其他型別維持關閉。`provenance` 維持收合。
- `fleeting` 的表單只有一個大文字框（見 A.4），不區分標題與內文。
- 送出後導向新卡片頁面，並在頁面頂端顯示一行「已從 ⟨來源卡標題⟩ 建立」，
  讓來源可一鍵返回。

## D. 遷移

型別語義在本次改動中變了，而既有卡片不可變也不帶版本標記。
這是這套架構唯一會靜默腐爛的地方。

修法是這個系統的自我應用，**在部署 v2 之前先做**：

1. 建立一張 `original`（無 url，A.4 允許），內容是 v1 的型別定義。
2. 建立一張 `thinking`，內容是 v2 的定義與改動理由，`updates` 指向上一張。

ID 可依時間排序，因此任何一張卡屬於哪一版定義，由它的 ID 與這張
thinking 的 ID 比較即可判定。不需要新增欄位。

程式面的遷移工作：**無**。舊卡片檔案完全不動，R4 保證它們不會因為
新規則而變成錯誤。重建索引後，違反 R1 的舊 `restatement` 會出現在
警告清單上，那是預期行為。

## F. 已裁決的邊界

這幾條是討論過程中被明確否決的做法，寫在這裡是為了避免日後又繞回來。

**「延伸 / 反駁」一律產生 `thinking`，不產生 `fleeting`。**
可以**從**一張 fleeting 延伸或反駁（來源是 fleeting，見 C.3），
但產生的卡片必然帶一條連結指回來源，而 R2 規定 fleeting 不得有連結。
兩者不能並存，R2 優先。

**`refutes` 不得指向 `restatement`。**
依 A.1，restatement 錯的方式是「我誤讀了」，那是 `updates` 的責任——
發一則新的重述取代它。「推翻一則重述」是類別錯誤：你不是在推翻
一個主張，你是在指出一次誤讀。所以 `restatement` 的 `+` 選單
沒有「反駁」，A.3 的 `refutes` 目標也只有 `thinking` / `fleeting`。

**側欄三項的名稱是「待思考 / 碎片 / 初步想法」。**
草稿裡出現過「未消化 / 尚未思考 / 懸空」，均已作廢。
