## A. 型別系統

### A.1 定義

型別的判準是**這張卡錯的時候該怎麼修**。不是篇幅，不是隨興程度。

| type | UI 標籤 | 對誰負責 | 錯的方式 | 修法 |
|---|---|---|---|---|
| `original` | 原始 | 不是我寫的 | 我抄錯了 / 存錯了 | 重存一份 |
| `restatement` | 重述 | 對原文負責 | 我誤讀了 | 重讀原文，發新的重述 `updates` |
| `thinking` | 思考 | 對世界負責 | 命題為假 | 換一個主張，發新的 thinking `updates` |
| `fleeting` | 碎片 | 尚未決定 | —— | 完整化成 thinking，或就讓它留著 |

`fleeting` 的存在理由：一句隨口的話需要一個不必負責的地方。塞進 `restatement` 會讓「我誤讀了」和「我想錯了」共用一格，而這兩種錯的修法完全不同。

它唯一預期的生命週期是**被完整化**：發一張 `thinking`，用 `updates` 指向它。那條鏈記錄「一個隨口的想法在哪一天變成一個主張」，是這個系統最有價值的產出之一。

> **型別名稱以本表為準。** 早期草稿的 `think` 是用詞漂移，正式名稱是 `thinking`。既有卡片檔裡已經是 `thinking`，解析器不認得其他寫法，改動會讓既有卡片解析失敗、從系統中消失。

### A.2 型別的硬性約束

**R1. `restatement` 必須至少有一條 `about` 指向 `original`。**
沒有原文可對照的東西不是重述。這條直接消除「參照對象是世界的 restatement」——那種卡片依定義是 `thinking` 或 `fleeting`。

**R2. `fleeting` 不得有任何連結。**
一旦開始建立關聯，做的就是 thinking 的工作。這條讓 fleeting 的建立成本真正降到「一個欄位」。

**R3. 每一型只能使用自己被允許的 rel（A.3），且目標型別必須符合。**
硬性規則，不是警告：**有方向的規則可以之後放寬，沒有約束的欄位只會發散。** 矩陣預期會隨使用調整，R4 保證調整對既有資料是免費的。

**R4. 規則改動不追溯既有卡片。**
既有卡片不可變，任何收緊或放寬都只作用於此後建立的卡片。重建索引時，違反現行規則的舊卡片列入報告的**警告清單**，不視為錯誤，不阻斷重建。

> R4 講的是「規則版本不追溯」，**不是**「編輯可以繞過規則」。反芻期內的修改視同建立的一部分，仍須通過當下的現行規則（D.3）。

### A.3 rel 詞彙表（依來源型別分）

| 來源 type | rel | 目標 type | 說明 |
|---|---|---|---|
| `original` | `part-of` | `original` | 摘錄卡片指向母文件 |
| `original` | `updates` | `original` | 換上更完整或更正確的副本 |
| `restatement` | `about` | `original` | **必填，至少一條**（R1） |
| `restatement` | `updates` | `restatement` | 修正誤讀 |
| `thinking` | `about` | `original` / `restatement` | 這則思考在講什麼 |
| `thinking` | `supports` | `original` / `restatement` / `thinking` | 這是我的依據 |
| `thinking` | `contradicts` | `thinking` / `restatement` | 兩者不相容，尚未裁決 |
| `thinking` | `refutes` | `thinking` / `fleeting` | 推翻 |
| `thinking` | `updates` | `thinking` / `fleeting` | 取代舊主張，或完整化碎片 |
| `thinking` | `related` | 任意 | 關係尚未定型 |
| `fleeting` | —— | —— | 不得有連結（R2） |

**`supports` 排除 `fleeting`**：隨口的一句話不能拿來當依據。這一刀同時給了 `supports` 與 `related` 一個**結構上**的差別——矩陣裡其他每一條都靠目標型別區分，若這兩條目標都是「任意」，它們在表單上會長得一模一樣，差別只剩一句說明文字，而「這是依據」還是「還不知道關係」正是建立當下最難做的判斷。

**`related` 只開放給 `thinking`**：它是唯一沒有語義的 rel，若每一型都能用，會變成萬用逃生口而讓整個詞彙表失去作用。

> 附加觀測（非設計約束）：索引裡有足夠資料可以算出各 rel 的使用比例。若 `related` 長期佔絕大多數，代表詞彙表沒有在做事，可考慮縮減。不必為了讓數字好看而在建立當下加摩擦。

### A.4 W1 警告

**卡片帶有 `refutes` 或 `updates`，但排除這些連結本身之後，沒有任何連結指向 `original` 或 `restatement`。**

排除自身是為了不讓「推翻一張原始資料卡」自己滿足自己的舉證要求。依據必須落在材料上；另一則 thinking 仍然只是意見——不附證據的推翻，跟改變心情無法區分。

W1 不阻擋寫入，只在卡片頁顯示。

### A.5 frontmatter：依型別的差異

共通欄位（四型皆有，序列化時一律寫出，用不到的填 `null`，讓檔案的長相不隨型別分歧）：

`id` `type` `created` `title` `tags` `url` `provenance` `revised` `links`

> 欄位名以現行程式碼為準：是 **`revised`** 不是 `revised_at`。

```yaml
# original
url: "https://..."      # 選填。沒有網址的一手材料（實體書、手稿）
                        # 同樣是 original，不該被擋在門外。
provenance: default | translated | AI-summarized     # 預設 default
source_author: "Herbert A. Simon"    # 選填，新增欄位
source_date: "1962"                  # 選填，自由字串，不解析

# restatement / thinking
# url 與 provenance 必須為 null。source_author / source_date 不適用。

# fleeting
# 整句話存在 title，body 為空字串。
# url / provenance / source_* 皆為 null。tags 允許但非必要。
```

**`fleeting` 的文字為什麼存在 `title`**：`title` 在現行系統裡是列表顯示、連結選擇器搜尋、分頁名稱、引用串標籤四處唯一的依靠。放進 `title`，這四處全部自動正確，而且「title 必填非空」的既有規則不必鬆動——**資料模型完全不動**。代價是跟「標題」這個詞的直覺相反，所以**介面上不呈現這個區分**：建立 fleeting 時只有一個大的文字區塊，不標 title 也不標 body；完整化成 thinking 時，這段文字填進新卡的 **`body`**。

**`source_author` / `source_date` 是新增欄位**：目前列表上 original 顯示的是內文開頭（「世界 By Yu An Chan — 27 Jul 2019 我的世界觀…」），零資訊。有了結構化欄位，列表可以顯示「Yu An Chan · 2019」加上引用計數。

### A.6 型別的呈現差異

現在四型長得一樣，所以型別在介面上不存在。修法不是配色，是**每一型的列表項與詳細頁提供什麼**。

| type | 列表項顯示 |
|---|---|
| `original` | 標題 · 作者 · 原始年份 · 「N 則重述 / M 則引用」。不顯示內文開頭。作者或年份缺漏時整個略過，不留空欄 |
| `restatement` | 標題 + 內文前兩行 · 它在講哪份 original |
| `thinking` | 標題 + 內文前兩行 · 出向連結數 · 入向連結數 |
| `fleeting` | 整句話（它就是全部內容） · 日期 |

詳細頁的主要動作見 C.3。

## B. 側邊欄：從儲存分類改為工作狀態

現行的「全部 / 標籤 / 碎片」都是儲存分類，都在回答「我有什麼」。沒有一個畫面在回答「我接下來要做什麼」。

新的結構，每項後面顯示數量：

```
Skynote          ← 點這個回首頁（即「最近」）
待思考   N
初步想法 N
碎片     N
沉澱     N
─────────
追加外部資料      ← 建立 original 的入口
標籤
搜尋
```

上半是**工作狀態**（都是待辦清單），下半是**動作與工具**。「追加外部資料」跟旁邊兩項格式不一致是刻意的——它是動作，另兩個是去處；建立 original 沒有別的自然位置（它沒有參照對象可以掛），而它又不該跟隨手記共用同一顆按鈕（見 C.2）。

原本的「最近」從清單裡拿掉了，側欄頂端的標題本來就是回首頁。

### B.1 清單的共通判準

三份待辦清單問的是同一個問題：**這張卡有沒有被接住。** 沒有人指向它，就代表沒有人接手，那它就是需要我再確認一次的東西。這不是型別或標籤的羅列，是一次過濾之後剩下的待處理項。

| 項目 | 查詢 | 意義 |
|---|---|---|
| 待思考 | `type='original'` 且沒有任何入向連結 | 收進來但沒有人接手 |
| 碎片 | `type='fleeting'` 且沒有任何入向連結 | 沒有被撿起來用過的隨手記 |
| 初步想法 | `type='thinking'` 且完全沒有連結（進出皆無） | 兩頭都懸空的想法 |
| 沉澱 | 尚可編輯的卡片 | 參照 D. 反芻期，讓還可以編輯的卡片以一覽的方式呈現 |
| 最近 | 全部，時間逆序，可依 type / tag 篩選 | |

- **待思考不區分母卡與節錄**：兩者都是 `original`，同一條判準。摘錄不是「還沒消化」，是**把待辦從整篇文章縮小到那幾段**——你切開它，代表你讀過並挑出了值得的部分，剩下的已經判斷不值得；而節錄卡自己還沒有入向連結，待辦責任精確地落在那幾段上。代價：若習慣是先隨手摘一句再回頭細讀，整篇會提早離開清單，沒摘到的部分不會再回到待辦。接受。
- **初步想法多一個條件**（出向也不能有）：它的問題不只是沒人接手，是它自己也沒有接住任何東西——一個既沒有依據、也沒有被使用的主張。
- **`restatement` 沒有清單，這是刻意的**：它的存在本身就是「已經做過的工作」，不是待辦。
- 「待思考」是唯一會**主動增長**的清單——每存一篇文章就多一項。這是這個系統要用來取代 SNS 時間所必需的：打開就有東西等著處理。

現行側邊欄的「碎片」指向 thinking 且無連結，那個語義移到「初步想法」，「碎片」改指型別 `fleeting`。**現行畫面上的標籤已經是錯的**，本次一併修正。

## C. 建立流程

### C.1 核心原則

**建立卡片的入口應該長在它的參照對象上，而不是全域。**

這是 I3 的直接推論：連結只能指向已存在的卡片，所以任何帶連結的卡片，你在建立它的時候一定已經在看目標了。「先導航、再建立」是自然順序；「先建立、再回頭找目標」把順序倒過來，而那正是目前需要手動貼 ID 的來源。

全域建立入口因此只服務**沒有任何參照的卡片**。

### C.2 全域入口：依動機分開，不共用一顆按鈕

沒有參照的卡片有截然不同的兩種動機——一個是把外面的東西收進來，一個是把腦袋裡的東西倒出來——共用一顆按鈕會讓兩邊都變鈍。

**一、右下浮動按鈕：隨手記**

展開後是**兩個欄位**（標題、內文）加一個送出鍵。型別由標題決定：

| 標題 | 建立的型別 | 文字存到哪 |
|---|---|---|
| 空白 | `fleeting` | 內文欄的文字存進 `title`，`body` 留空（見 A.5） |
| 有填 | `thinking` | 照常，標題進 `title`、內文進 `body` |

沒有型別選單、沒有標籤、沒有連結。**不填標題就是碎片**——這是這個系統唯一的生死線：憑空記一句話如果需要一次型別決策，它就輸給 Discord。而「要不要給它一個名字」本來就是你在寫的時候自然會做的判斷，不是額外的決策。

> 實作要注意：`fleeting` 的欄位對應是反的——使用者填的是「內文」欄，但存進 `title`（見 A.5）。完整化成 thinking 時再填回新卡的 `body`。

現行左下的「＋ 建立卡片」與這顆功能重複，**移除左下那個**。

**二、側欄的「追加外部資料」：建立 original**

一篇剛讀到的文章沒有參照對象，只能從全域進來。點進去是完整的 `original` 表單：標題、url（顯眼位置，見 C.4）、內文、`source_author`、`source_date`、標籤。

### C.3 卡片詳細頁的 `+`

每張卡片的詳細頁右下有一個 `+`，按下去跳出小選單。**選單裡有哪些按鈕，由當前卡片的型別決定**；每個按鈕都預填好新卡片的型別與那條連結，使用者不需要知道 R1/R3 這些規則存在。

| 當前卡片 | 按鈕 | 建立什麼 | 預填的連結 |
|---|---|---|---|
| `original` | 節錄 | `original` | `part-of` → 本卡 |
| `original` | 更新 | `original` | `updates` → 本卡 |
| `original` | 重組織 | `restatement` | `about` → 本卡（滿足 R1） |
| `original` | 發想 | `thinking` | `about` → 本卡 |
| `restatement` | 發想 | `thinking` | `about` → 本卡 |
| `restatement` | 引證 | `thinking` | `supports` → 本卡 |
| `restatement` | 牴觸 | `thinking` | `contradicts` → 本卡 |
| `restatement` | 更新 | `restatement` | `updates` → 本卡 |
| `thinking` | 發想 | `thinking` | `related` → 本卡 |
| `thinking` | 延伸 | `thinking` | `supports` → 本卡 |
| `thinking` | 反駁 | `thinking` | `refutes` → 本卡 |
| `thinking` | 牴觸 | `thinking` | `contradicts` → 本卡 |
| `thinking` | 更新 | `thinking` | `updates` → 本卡 |
| `fleeting` | 完整化 | `thinking` | `updates` → 本卡，**內文預填本卡的文字** |
| `fleeting` | 反駁 | `thinking` | `refutes` → 本卡 |
| `fleeting` | 發想 | `thinking` | `related` → 本卡 |

- 「節錄」的標題自動取選取文字前 40 字，可改。
- 「更新」與「完整化」機制相同（`updates` → 本卡），分兩個名字是因為語義不同：更新是「換一個更好的版本」，完整化是「把隨口的話變成主張」。對`supports`語意不同也是同理，參照外部來源是引證，作為自己的話語的脈絡承接是延伸。
- **`fleeting` 沒有「延伸」**（`supports` 排除 fleeting），**`restatement` 沒有「反駁」**（那是 `updates` 的責任）。理由見 H。
- 每型三到五顆按鈕。選單在手機上要維持單手可及。
- `original` 詳細頁維持現有的分割視窗（左讀右寫），「引用選取的段落」按鈕保留在來源面板上，與 `+` 選單並存。
- 從卡片延伸出來的那條links沒辦法被刪除，只能調整連結的類型。

### C.4 表單本身

- 連結欄的標題搜尋已完成，維持。
- 型別選擇維持在表單最前面，但**由入口決定預設值**，多數情況不需要碰它。
- `url` 對 `original` 是主要欄位，**從收合區移出來**放到顯眼位置；其他型別維持關閉。`provenance` 維持收合。
- `fleeting` 的表單只有一個大文字框，不區分標題與內文（見 A.5）。
- 送出後導向新卡片頁面，頂端顯示一行「已從 ⟨來源卡標題⟩ 建立」，讓來源可一鍵返回。

## D. 反芻期

### D.1 窗口長度

**R5. 卡片自建立起有一段可修改的反芻期，長度由 `EDIT_WINDOW_HOURS` 決定，預設 8 小時。**

不是五分鐘：五分鐘只夠對齊字句。思維本來就會迭代，一個衝動記下的東西需要一段窗口去補完還沒迭代完的內容，而不只是做非結構式的調整——那段時間要用來想「哪些才是真正該被記錄的」。8 小時跨得過一個工作段落與一次睡眠。

這是行為參數，靠使用經驗調整，所以放在環境變數而不是程式碼裡；它只改變「還能不能改」，永遠不會回頭改寫已經寫好的東西。

### D.2 定案：被指向就關窗

**R6. 一旦有任何卡片的 `links` 指向這張卡，它立刻定案，不再可改、不再可刪，不論反芻期是否結束。**

這條取代「時間到就鎖」這個沒有理由的數字，換成一個因果條件：**有人開始依賴你，你就定案了。** 它同時管住三件事——從待辦清單移出、關閉編輯、禁止刪除——三件事一個判準。

它也是反芻期能夠拉長的前提。引用錨點 `#b{n}` 的正確性建立在「來源的區塊結構不會變」之上；沒有 R6，八小時的窗口會讓「B 引用 A 之後 A 又改了內文」變成日常，而那種腐爛不會報任何錯。

> R6 只看 frontmatter 的 `links`，正文裡的引用連結不另外索引。殘留風險：刪掉連結列之後才插引用，就會有錨點而沒有鎖。已知，選擇不為它增加機制。

### D.3 反芻期內可以改什麼

| 欄位 | 可否修改 |
|---|---|
| `title` `body` `tags` `url` `provenance` | 自由增刪改 |
| `links` | **只能新增，不能刪除或修改**（R7） |
| `type` `id` `created` | 不可改 |

**R7. 反芻期內 `links` 只增不減。**
新增的每一條都要通過當下的現行規則（R3 的 rel 與目標型別、目標必須存在且 ID 較小、同 rel 同目標不得重複）。既有連結不動，因此不需要重驗，R1 也不會因為編輯而被破壞。

只增不減讓連結的編輯落在 append-only 的整體哲學裡，而不是一個例外。代價是**選錯了就收不回**——這正是 R9 存在的理由，它不是方便功能。

**R8. `fleeting` 在反芻期內不得新增連結。** R2 優先；fleeting 的編輯表單不出現連結欄位。

**`type` 不可改**：改型別等於換一個「錯的時候怎麼修」的標準，那是一張新卡片的工作，用 `updates` 指回舊的（見 A.1 的修法欄）。架構上要讓這件事日後可以開放，但現在不開。

### D.4 刪除

**R9. 反芻期內、且尚未被任何卡片指向的卡片可以刪除。**

這推翻了 v1 的「沒有任何 endpoint 能刪除卡片」以及對應的驗收條件。理由：R7 讓誤加的連結無法收回，若連整張卡都不能刪，一次手滑就永久留在語料庫裡。刪除是 R7 的必要配套。R6 保證被指向的卡片刪不掉，所以刪除永遠不會製造壞連結。

刪除走一次 `rm {id}` 的 commit。ID 永不重用（時間序 ID 本來就不會）。

> **刪除不等於抹除。** 卡片在建立當下就已經 commit、可能已經 push，刪除只讓檔案從 `cards/` 消失，內容仍留在 git 歷史裡。這是備份該有的行為，接受。

### D.5 可見性

還在反芻期內的卡片要看得見，否則窗口等於不存在。在卡片頁顯示剩餘時間；已被指向而提前定案的顯示定案狀態而非倒數。

## E. 遷移

型別語義在本次改動中變了，而既有卡片不可變也不帶版本標記。這是這套架構唯一會靜默腐爛的地方。

修法是這個系統的自我應用，**在部署 v2 之前先做**：

1. 建立一張 `original`（無 url，A.5 允許），內容是 v1 的型別定義。
2. 建立一張 `thinking`，內容是 v2 的定義與改動理由，`updates` 指向上一張。

ID 可依時間排序，因此任何一張卡屬於哪一版定義，由它的 ID 與這張 thinking 的 ID 比較即可判定，不需要新增欄位。

程式面的遷移工作：**無**。舊卡片檔案完全不動，R4 保證它們不會因為新規則而變成錯誤。重建索引後，違反 R1 的舊 `restatement` 會出現在警告清單上，那是預期行為。

## F. 工程結構

現行 `registerRoutes` 是單一函式數百行，把 HTTP 解析、業務決策、儲存編排、呈現轉換四件事放在一起。本次要帶進的 per-type 分支有三個維度（規則矩陣、列表呈現、`+` 選單），塞進現行結構會直接長成 if/else 叢林。

**先重構，再疊功能。** 重構是純搬移，不改行為，既有測試保持全綠；兩件事混在一起做會分不清是哪一邊弄壞的。

```
domain/   規則。不知道 HTTP，也不知道 SQL
  types   型別、rel 詞彙、per-type 矩陣（唯一的真相來源）
  rules   R1–R9、W1
  card    Card 結構與序列化
store/    落地
  files   cards/ 讀寫
  index   SQLite：schema / write / query / rebuild 各自成檔
  backup  git
service/  用例，把 domain 與 store 串起來
  cards   create / update / delete
  lists   待思考 / 碎片 / 初步想法 / 最近
web/      只做 HTTP
  routes  解析 → 呼叫 service → 選模板
  present row → view model
  views
```

兩條擋住膨脹的紀律：

1. **每一條規則是 `rules` 裡的一個具名函式。** 路由與模板問同一個函式，不各自算一遍——「這張卡能不能編輯」目前就是兩處各判一次。
2. **per-type 的差異集中在表格資料裡**（A.3 矩陣、A.6 呈現、C.3 選單），不散在條件分支裡。

實作順序：

- **Phase 0** 抽象層重構。純搬移，不改行為。
- **Phase 1** 型別系統：四型、R1–R4、rel 矩陣、側欄清單、per-type 呈現、兩個全域入口、詳細頁 `+` 選單。
- **Phase 2** 反芻期：R5–R9、可見性、刪除。

## H. 已裁決的邊界

**「延伸 / 反駁」一律產生 `thinking`，不產生 `fleeting`。** 可以**從**一張 fleeting 反駁或完整化（來源是 fleeting，見 C.3），但產生的卡片必然帶一條連結指回來源，而 R2 規定 fleeting 不得有連結。兩者不能並存，R2 優先。

**`refutes` 不得指向 `restatement`。** 依 A.1，restatement 錯的方式是「我誤讀了」，那是 `updates` 的責任——發一則新的重述取代它。「推翻一則重述」是類別錯誤：你不是在推翻一個主張，你是在指出一次誤讀。

**`supports` 不刪除，改為收窄目標型別。** 曾考慮刪掉它，因為在使用感受上與 `related` 難以區分。原因診斷出來是矩陣問題而非語義問題：兩者原本的目標都是「任意」，在表單上完全對稱。收窄後差別變成結構性的，同時也讓 W1 有可判定的依據。

**「初步想法」不另開一份「已被引用但仍無依據」的清單。** 曾提議在清單底下掛一行計數，指出那批「自己沒依據、卻已經被別人當依據」的卡片。未採用：待辦清單要保持乾淨，等實際使用後再評估。

**引用鎖只看 frontmatter 的 `links`，不索引正文裡的引用連結。** 見 D.2 的但書。不為殘留風險增加一張索引表。

**不加領域維度欄位。** 跨領域混雜本身不是問題——這個系統最有價值的東西恰恰是不同領域之間那條意外的連結，按領域切開會殺掉它。真正會痛的是量大之後時間軸變成噪音，而那是探索機制的問題，不是資料結構的問題；探索機制屬於目前明確排除的圖形視覺化。先不動。
