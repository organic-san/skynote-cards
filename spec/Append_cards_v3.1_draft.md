## 1. 背景

### 1.1 要回應的觀察

v3 草案 2 §1 記錄了設計假設與實際用法的落差。其中兩項由本文件的環境回應：

1. **跨分野的雜訊。** 首頁是一條混著所有主題的時間軸，不同脈絡的內容互相干擾。
2. **缺一個放的地方。** 還留在 Discord 的幾種用法（TODO、紀錄、想做的事、旅遊紀錄），缺的幾乎都是同一樣東西：一個放的地方（v3 草案 2 §1.2）。

v3 草案 2 §1.3 的原則同樣適用：**機制只提供原件，流程留在使用習慣裡。** v3 補的原件是勾選，本文件補的是另一個：環境。

§5 的背景是同一份紀錄的第三點：不可變的價值在放鬆，不在限制（v3 草案 2 §1.1）。

### 1.2 檢驗方式【待確認】

環境上線後，先只開一個新環境，把 TODO 與紀錄搬進來。一個月後檢查這兩樣還在不在 Discord：還在，代表這個方向沒有解決問題，應停止投入。

## 2. 環境

### 2.1 定義【已定】

**一個環境就是一份完整的 Skynote。** 它有自己的首頁時間軸、標籤、搜尋、沉澱清單與隨手記。在一個環境裡看不到其他環境的卡片。

- **劃分的依據是專注脈絡**，例如：雜事與資料、繪圖、學校、專題、自我省思、故事與創意發想。同一個環境裡可以混用 TODO、紀錄與思考。
- **各環境的規則完全一致。** 型別、rel 矩陣、反芻期、定案，在每個環境都相同。
- **引用可以跨環境。** 例如專題最早的發想，來自故事與創意發想。
- **既有卡片屬於「沒有環境」。** 它們原地不動，「沒有環境」是一個長期存在的空間，不是待清空的暫存區。
- **環境不是標籤的另一種呈現。** 標籤與空間混用會讓兩者都變得雜亂，所以環境是標籤之上、真正分離的一層。

### 2.2 資料配置

環境在資料面就是在既有的 `cards/` 底下多開資料夾【已定】。路徑的確切形式如下【待確認】：

```
corpus/
  cards/
    {id}.md            ← 沒有環境。既有卡片原地不動
    繪圖/{id}.md       ← 環境「繪圖」
    學校/{id}.md       ← 環境「學校」
  tags.yml
```

- **環境的身分就是資料夾名稱，卡片檔案不記錄自己在哪個環境。** frontmatter 因此一個欄位都不用加，既有卡片不需要改寫。
- **ID 全域唯一。** 發號時的碰撞檢查必須涵蓋所有資料夾；現況的 `fileExistsTaken` 只看 `cards/` 這一層。
- **依 ID 找檔案不得依賴索引。** 檔案是唯一真相，索引只是投影。環境數量很少，逐一資料夾檢查即可。
- **資料夾只有一層**，不巢狀。
- **環境名稱的限制**：去除首尾空白後不得為空；不得含 `/ \ < > : " | ? *` 與控制字元；不得以 `.` 開頭；長度上限 40 字。限制比 Linux 檔名嚴格，因為語料庫可能被 clone 到其他系統。
- **git**：一張卡一個 commit 不變，`commitCard` 的路徑要帶上資料夾。`commitPendingCards` 以「`cards/` 開頭、`.md` 結尾」判斷卡片檔，對子資料夾已經成立。
- **建立環境**是一個明確的動作（側欄的「新增環境」），效果是建立資料夾。空資料夾不會進 git，這沒有關係：沒有卡片的環境沒有東西需要備份。
- **不設清單檔**記錄環境與順序【待確認】。存在哪些環境由資料夾決定，側欄的順序依各環境最近一張卡的建立時間。
- **手動建立的環境**：在別處的 clone 裡開好資料夾、放進卡片再 push，用側欄的「更新」取回之後就會出現（v3 §7）。

環境的改名、刪除與卡片的移動，本草案不提供介面（§6）。

### 2.3 索引

- `cards` 表加一欄 `env TEXT NOT NULL DEFAULT ''`，空字串代表沒有環境，並為它建索引。
- `SCHEMA_VERSION` 遞增。照既有慣例，版本不合就整個重建，不寫遷移。
- 重建時掃描 `cards/` 與其下一層資料夾。
- **以環境為界的查詢**：`listCards`、`tagCounts`、`search`、`settling`，以及側欄下半的最近標籤與最近卡片（v3 §5）。
- **維持全域的查詢**：`getCard`、`typeOf`、`isCited`、`outLinks`、`backLinks`、`linkTree`、`pickerSearch`。

### 2.4 路由與「目前所在的環境」【待確認】

- **沒有環境**：既有網址全部不變（`/`、`/tags`、`/search`、`/settling`、`/new`、`/quick`）。既有書籤與測試不受影響。
- **環境**：加上前綴 `/e/{env}/`，其下是同一組路由。
- **卡片頁** `/c/{id}` 維持全域，不帶環境。頁面的外殼（側欄、隨手記）以這張卡所屬的環境為目前環境。
- **不記憶上次所在的環境。** 伺服器不保存這個狀態；想直接進某個環境，把它的網址存成書籤。

用網址前綴而不用 cookie，理由是網址可以存書籤、可以同時開兩個分頁各看一個環境，而且伺服器維持無狀態。

草稿槽（v2.2 §2 的 `data-draft-scope`）要帶上環境，否則兩個環境的隨手記會共用同一格草稿。以卡片 ID 為鍵的槽（`edit:{id}`、`new:{type}:{rel}:{srcId}`）不受影響。

### 2.5 各功能的範圍

| 功能 | 範圍 | 說明 |
|---|---|---|
| 首頁時間軸、型別與標籤篩選 | 目前環境 | |
| 標籤頁、表單的標籤推薦 | 目前環境 | 同名標籤在不同環境各算各的 |
| 沉澱清單、側欄下半的最近標籤與最近卡片 | 目前環境 | 卡片頁的外殼以那張卡所屬的環境為目前環境（§2.4） |

| 標籤鎖定（`tags.yml`） | 全域 | 維持根目錄一份，不分環境【待確認】 |
| 卡片 ID、`/c/{id}`、段落錨點 `#b{n}` | 全域 | |

### 2.6 新卡落在哪個環境

- **隨手記（含展開之後的思考與產出，v3 §4.3）、追加外部資料、裸的 `/new`**：目前所在的環境。
- **卡片頁的 `+`**：預設是來源卡的環境，表單上顯示並可以改選【待確認】。跨環境衍生是明確的需求（§2.1）。
- **建立之後不能改環境**，反芻期內也不行。放錯了就刪除重建（R9）：一般卡片限反芻期內，產出在被引用之前都可以（v3 §3）。§5 不影響這一條：環境不是文字欄位。
- **標籤繼承**（v2 C.3）照舊。標籤只是卡片上的字串，跨環境衍生時會計入新環境的統計。

  （無環境）
  繪圖
  學校
  ＋ 新增環境
─────────

環境清單放在最上面，因為它決定了下面每一項指的是哪裡。它用的是三份待處理清單空出來的位置（§3）。「沒有環境」在介面上的名稱待定。

### 2.8 推翻 v2 G 節的裁決

v2 G 節「**否決增加領域分類維度**：跨領域思維碰撞是卡片盒的核心價值，硬性領域切割會扼殺意外的關聯發現」，由本節推翻。

理由：實際使用下來，跨分野雜訊的代價高於意外關聯的收益。原裁決要保護的東西由跨環境連結保留——卡片仍然可以指向任何環境的任何一張卡。

## 3. 側欄移除三份待處理清單【待確認】

移除「待思考」「初步想法」「雜筆」，保留「沉澱」。

- **理由**：實際使用中只有「沉澱」在用。另外三份問的是「收進來的東西有沒有被接住」（v2 B.1），那是 v3 草案 2 §1.1 所說的設計假設，與實際用法不符。
- **改動**：`routes.ts` 的 `WORK_LISTS` 與 `shell` 的清單定義、`lists.ts` 的三支函式、`query.ts` 的三句查詢、對應的測試。
- **對既有規格的影響**：v2 B 節的側欄結構與 B.1 的三份清單、v2.1 的 U8 失效；U9 只剩「沉澱」適用。
- **保留的「沉澱」**：定義是反芻期內且未被引用的卡片，不列產出（v3 §3）。§5 若採用，它的意思會變成「還能補連結、還能刪除的卡」。

## 4. 首頁短文的顯示範圍拉長【待確認】

文章不長的時候，在首頁多顯示一些，不必點進去才讀得完。

現況有兩道截斷：伺服器的 `excerpt()` 把內文壓平成 90 字並去掉換行，CSS 再截成兩行（v2.1 的 U34）。只改 CSS 沒有用。

建議的做法：

- 字數上限提高，並保留換行。
- 行數上限由 2 行提高到約 6 行。
- 列表上不渲染 Markdown。
- 只作用於時間軸；搜尋結果維持命中片段。

以上數值皆為暫定。拉長會讓每一則佔的面積變大，在環境切開之前會放大跨分野的雜訊，所以排在 §2 之後。

## 5. 未被引用的卡片可以一直修改【暫緩】

> v3 決定反芻期暫時保留（v3 草案 2 §9）。本節保留提案與分析，等需要時再決定。

### 5.1 動機

反芻期（R5，預設 8 小時）原本的用意，是留一段時間回頭審視與潤飾（v2 D.1）。實際用下來，這個期限對修正小錯誤與補述的意義不大。

檢查它實際保護了什麼：需要保護的是**被依賴的東西**，而那由 R6 負責——被指向的卡片定案（v2 D.2）。沒有被指向的卡片，改了也不會讓任何結構化連結失效（正文裡的段落連結見 §5.5）。時間限制在 R6 之外多擋下的，是對沒人依賴的卡片所做的修改，小修正與補述就屬於這一類。

v3 的產出已經走在前面：產出不設反芻期，被引用之前修改、加連結、刪除都不受時間限制（v3 §3）。本節要決定其他型別是否跟進，以及跟到哪裡。

### 5.2 做法一：只放開文字欄位（本草案建議）

**R5（修訂候選）. 卡片自建立起有一段反芻期，長度由 `EDIT_WINDOW_HOURS` 決定，預設 8 小時。反芻期只管連結的新增（R7）與刪除（R9）；文字欄位的修改不受反芻期限制，只受 R6 限制。**

v2 D.3 的修改約束改為：

| | 反芻期內、未被引用 | 反芻期後、未被引用 | 被引用（R6） |
|---|---|---|---|
| `title` `body` `tags` `url` `provenance` `source_*` | 可改 | 可改 | 不可改 |
| `links` | 只增不減（R7） | 不可新增 | 不可新增 |
| 刪除整張卡（R9） | 可以 | 不可以 | 不可以 |
| `type` `id` `created` | 不可改 | 不可改 | 不可改 |

連結與刪除留在反芻期內，理由有三：

- **刪除是連結的配套。** R9 存在是因為 R7：連結選錯收不回，只能整張刪掉重建（v2 D.4）。如果連結可以一直加、刪除卻只限反芻期，反芻期後加錯的連結就再也沒有補救的方法。兩者必須同一個期限。
- **反芻期後的關聯是新的思考。** 「發現兩個舊想法有關，本身就是一個新的思考，它應該有自己的節點」（MVP I4）。反芻期後要把舊卡連到更舊的卡，就發一張新卡同時指向兩者。
- **刪除比修改重。** 修改留下同一張卡，刪除讓它從時間軸上消失。手滑通常當下就會發現，反芻期足夠。

R4 的但書「反芻期內的修改視同建立的一部分」改為「修改視同建立的一部分」：不論何時修改，都要通過當下的現行規則。規則收緊之後，修改一張不合新規則的舊卡，要在同一次修改裡讓它合規（例如沒有標籤的舊 `thinking`，v3 §4）。

### 5.3 做法二：全部不設期限，比照產出

連結的新增與刪除也取消期限，「能不能動」只剩「有沒有被引用」一個判準。

- **好處**：規則只有一條，反芻期整個退場，所有型別與產出一致。
- **代價**：反芻期後加錯的連結只能整張刪掉重建，而重建會換掉 ID 與建立時間，對一張舊卡來說就是失去它在時間軸上的位置；沉澱清單要重新定義。
- **產出接受這個代價的理由**，是改稿時補上取材的連結是常態（v3 §3）。其他型別沒有這個需要。

### 5.4 連帶的變化

- **判準拆成兩個**（做法一）：「文字能不能改」只看 R6；「連結與刪除能不能動」看 R5 與 R6。
- **沉澱清單**：做法一定義不變，意思變成「還能補連結、還能刪除的卡」，空狀態的文字「沒有任何卡片仍在可修改時間內」要跟著改；做法二要重新定義。
- **卡片頁**：meta 行末尾的「尚可編輯 N 小時」（v2 D.5）移除。文字能不能改不再有期限，留著這個倒數，會讓人以為時間到了就不能改。「編輯」鈕照舊只在可改時出現，判準改為「沒有被引用」。
- **編輯頁**：做法一的倒數改說連結與刪除的期限，例如「連結與刪除還剩 3 小時」；反芻期後，新增連結的區塊與刪除鈕不再出現，換成一行說明。做法二沒有倒數，比照產出。
- **鎖定時的訊息**：只剩被引用一種原因。
- **R14**：未被引用的卡片本來就能改，R14 實際作用的只剩被引用的卡片，以及不更新 `revised`（v3 §2）。
- **`revised`**：每次修改照舊更新。卡片頁的「改於」會比以前常出現，這是預期的。

### 5.5 風險：手動貼上的段落連結

R6 只看 frontmatter 的 `links`（v2 G 節「否決正文引用參與定案鎖定」維持，見 v3 草案 2 §9）。應用程式產生的段落連結只有一個來源：來源面板的「引用」鈕，而那條路徑一定帶著指回同一張卡、拿不掉的連結（v2 C.3、R7），所以都在 R6 的保護範圍內。

不受保護的只剩手動貼進正文的網址。期限放開之後，它們指向的段落可能位移；需要穩定的錨點時，建立連結。

## 6. 暫不處理

- **環境的改名、刪除與卡片的移動。** 移動卡片在資料面只是搬動檔案，內容逐位元不變，所以不牴觸不可變；日後要做，不需要動規則。

## 7. 裁決紀錄（G 節補充）

1. **推翻「否決增加領域分類維度」**（§2.8）。跨分野雜訊的實際代價高於意外關聯的收益，後者由跨環境連結保留。
2. **環境不進規則層，各環境規則一致。** 個別環境有自己的規則，會回到規則互不一致、操作不自由的問題。
3. **環境以資料夾表達，不寫進 frontmatter。** 既有卡片不必改寫，日後搬動卡片也不必改動內容。
4. **否決以標籤作為分隔機制。** 標籤與空間混用會讓兩者都變得雜亂。
