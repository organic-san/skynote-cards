## 1. 時間軸的內文開頭

### 1.1 動機

文章不長的時候，在首頁多顯示一些，不必點進去才讀得完。

先前有兩道截斷：伺服器的 `excerpt()` 把內文壓平成 90 字並去掉換行，CSS 再截成兩行（v2.1 的 U34）。壓成一行之後，條列與分段的結構也一起消失，連認都不好認。只改 CSS 沒有用。

### 1.2 做法

**伺服器（`src/web/present.ts` 的 `excerpt()`）**，依序：

1. 程式碼區塊（` ``` ` 圍起來的）整段拿掉。
2. 逐行剝掉記號：引言的 `>`、標題的 `#`（`#` 後面要有空格才算標題，`#標籤` 開頭的一行照留）、強調與行內程式碼的 `*` `_` `` ` `` `~`；連結與圖片只留文字。
3. 條列的 `-` `*` `+`（含待辦的 `[ ]` `[x]`）換成「・」。編號清單照留。
4. 空行，以及分隔線、表格的對齊列（`|---|:-:|`）整行拿掉。
5. 取前 `EXCERPT_LINES`（5）行，以換行接起來；超過 `EXCERPT_CHARS`（300）字再截。有截到就以「…」收尾。字以碼位算，中文一個字算一個，換行也算一個。

列表上不渲染 Markdown：這裡要的是認得出這張卡，不是讀一份排好的文件。

**畫面（`src/web/views/cardlist.eta`、`public/css/list.css`）**：時間軸的內文開頭多一個 class `rowlines`，`white-space: pre-line` 排出換行，`-webkit-line-clamp: 8`。`.rowtext` 本身的兩行截斷（U34）不動，搜尋的命中片段照它。

**範圍**：時間軸，包含標籤、型別篩選與「已隱藏」（§2.3）。搜尋結果有命中片段時用片段，維持兩行。資料（`original`）的列照舊不顯示內文，改列出處（v2.1 U5）。碎片走同一支函式，它那段話一樣保留換行。

### 1.3 兩種「行」

原文的一行可能是一整段長文，在直式螢幕上會折成好幾行。所以有兩道限制，各管一件事：

- **伺服器的 5 行、300 字**算的是原文：保留前幾段的結構，不讓一張長卡把整份原文送進列表。
- **CSS 的 8 行**算的是畫面：一段長文在窄欄裡折行之後，不會把一列撐得太高。

兩個數值都是常數（`EXCERPT_LINES`、`EXCERPT_CHARS`、`list.css` 的 `.rowlines`），用一陣子再調。

## 2. 已被更新或反駁的卡

### 2.1 動機

首頁上，「我現在怎麼想」跟「我以前這樣想、後來推翻了」排在一起，舊卡沒有任何記號。要點進舊卡、捲到最下面的引用串，才看得到「被反駁」或「更新出」。這帶來兩件事：時間軸變雜，而且讀到舊卡時會以為它還成立。

本版之後，**時間軸列的是目前還成立的卡**，不再是寫過的全部。被取代的卡不刪、不改，只是不列在時間軸上；從篩選列、搜尋、引用串都還找得到。

### 2.2 判準

**一張卡只要有任何一條 `updates` 或 `refutes` 指向它，就算已被取代。**

- **`contradicts` 不算**：它說的是兩者不相容、還沒裁決，誰也沒推翻誰。
- **不往回推**：A 被 B 反駁、B 又被 C 反駁，A 不會因此回到時間軸。系統判斷不了 C 推翻的是 B 的哪一部分；要讓 A 回來，就發一張新卡。
- **碎片的「完整化」也算**：它走的就是 `updates`（v2 的 CARD_ACTIONS）。完整化過的碎片從時間軸上消失，這是想要的效果——那段話已經長成一張思考了。
- **跨環境也算**：連結可以跨環境（v3.1 §2.5）。B 在環境 Y、更新了環境 X 的 A，X 的時間軸一樣不列 A；A 的卡片頁提示會連到 B，並標出 Y。
- **寫不進卡片檔**：舊卡被新卡指著，R6 已經把它鎖住（I2 也不允許）。「已被取代」是索引上的一個查詢，每次從 `links` 表算出來：`NOT EXISTS (SELECT 1 FROM links WHERE target_id = c.id AND rel IN ('updates', 'refutes'))`，走既有的 `idx_links_target`。schema 不變，不需要重建索引。

判準的唯一真相來源是 `src/domain/types.ts` 的 `SUPERSEDING_RELS`。

### 2.3 時間軸與篩選列

- **時間軸不列**：首頁、標籤的時間軸（`/?tag=…`）、型別篩選（`/?type=…`）都不列已被取代的卡。篩選列右端的總數與分頁也不算它們。
- **篩選列多一個「× 已隱藏」**，排在碎片右邊。型別前面是色點，這一格前面是一個 ×（`icon.eta` 的 `x`，淺灰），不顯示數量。這個環境（有選標籤時是這個標籤）裡沒有已被取代的卡，這一格就不出現。
- **點下去（`/?hidden=1`）只列已被取代的卡**，同樣依時間逆序、同樣帶著標籤。它跟型別篩選是同一排互斥的選項：網址同時帶 `hidden=1` 與 `type` 時只認「已隱藏」。
- **「全部」名字不變**：它不含已隱藏的卡，但不改名。
- **側欄的最近卡片**（v3 §5）也不列。

### 2.4 不受影響的地方

- **標籤頁的計數照算被取代的卡**（使用者裁決）：那個數字記的是在這個話題上打轉了幾次，不是現在還成立的有幾張。所以標籤頁寫「#物理 5」、標籤的時間軸列 3 張是正常的，差的兩張在那個標籤的「已隱藏」裡。表單的標籤推薦用同一份計數，也照算。
- **搜尋**照樣列，也不另外標記：找舊卡是搜尋的用途之一。點進去之後卡片頁會說它已被取代。
- **引用串與連結的選卡器**照樣列。
- **側欄的環境排序**（卡片數、最近一張的時間，v3.1 §2.8）照算。

### 2.5 卡片頁頂端的提示

已被取代的卡，卡片頁的**第一行**是一塊淺紅底的提示，排在標題之上：

```
本文已被更新：〈新版的標題〉、〈另一個新版〉
本文已被反駁：〈反駁它的那張〉
```

- **說法**：`updates` 是「本文已被更新」；碎片被 `updates` 指到時是「已完整化」；`refutes` 是「本文已被反駁」。說法之後接全形冒號，再列出卡片。更新在前、反駁在後，同一種有好幾張時全部列出，以頓號隔開。
- **只列直接指過來的那幾張，不追到鏈尾**：A ← B ← C 時，A 的提示連到 B，B 的提示再連到 C。
- 標題嵌在句子裡，所以截到 24 字（同「已從 X 建立」，見 `present.ts` 的 `clip`）。另一頭在別的環境時，標出那個環境名。
- **樣式**：底色 `--superseded-bg`（`#FCE6E3`，新 token），標示字用 `--alert`（錯誤訊息的磚紅），連結加底線。底色左右溢出 `--hover-bleed`，文字左緣仍跟標題對齊。
- 提示是渲染時從反向連結算的（`routes.ts` 本來就為了下游的筆數查 `backLinks`，現在共用那一次查詢）。

## 3. 網路字型改回每一種裝置都載

**做法**：`layout.eta` 的 Google Fonts 樣式表拿掉 `media="(pointer: coarse)"`，電腦與手機都載 Noto Sans TC。

**理由**（使用者）：全局一致的行為。電腦與手機用同一份字型，不再依裝置分岔。

**代價**：v3.1 §4.3 量過，電腦上不載網路字型時，Ferdium 換頁露出黑格的比例從 5 / 12 降到 1 / 24。那時的原因是：字型切成十幾個字檔，每換一頁都要在畫第一格之前重新解碼。v3.1 §4.4 的換頁不換文件（nav.js）之後才上線，字型解碼還會不會造成一閃，本版沒有重新量。如果又看到閃，這是第一個要查的地方。

**測試**：`test/v3.1.test.ts` 原本要求這個樣式表帶著 `media="(pointer: coarse)"`，改成要求它不帶 `media`。模板裡的樣式表只能是網路字型、自己的 CSS 嵌進頁面，這兩條照舊。

## 4. Markdown 工具列與清單延續

### 4.1 動機

內文的 Markdown 語法要手打。最常重複的是待辦的 `- [ ] `：手機上要切到符號鍵盤才打得出方括號，而且每一項都要再打一次。v3 §2.4 的 TODO 習慣（每天一張卡、一行一項）正好是重複最多的地方。

本版之後，文字框上方多一排按鈕，點一下就插入語法；在清單項目上按 Enter，下一行會自動帶出同樣的記號。**文字框仍然是原生的 textarea**，送出去的就是框裡的原文，這兩樣東西只是替你打字。

### 4.2 範圍

- **有工具列的**：建立表單與編輯表單的「內文」，以及碎片的那一格文字框（建立表單的 `#singlefield`、碎片的編輯頁）。碎片的那段話也渲染成 Markdown，待辦一樣能勾（v3 §2.3），所以一起放。
- **隨手記不放**：它要的是快（v3 §4.3），多一排按鈕就多一份視覺負擔。
- **沒有 JS 時**整列不顯示（`html:not(.js) .mdbar`），文字框照常能用。

### 4.3 按鈕

由左到右九顆，以分隔線分成三組：

| 按鈕 | 作用 | 已經是這個狀態時再按 |
|---|---|---|
| 待辦 | 行首加 `- [ ] ` | 拿掉 |
| 已完成 | 行首加 `- [x] ` | 拿掉 |
| 清單 | 行首加 `- ` | 拿掉 |
| 編號清單 | 行首加 `1. `；上一行是同一層的編號，就接著往下編 | 拿掉 |
| 引用 | 行首加 `> ` | 拿掉一層 |
| 粗體 | 包成 `**…**` | 拿掉 |
| 斜體 | 包成 `*…*` | 拿掉 |
| 程式碼 | 包成 `` `…` ``；選了好幾行就改成 ` ``` ` 區塊 | 拿掉（區塊不收回） |
| 連結 | 選的是字：`[字]()`，游標停在括號裡；選的是網址（`http(s)://` 或站內的 `/…`）：`[](網址)`，游標停在方括號裡 | — |

**行首的五顆**（待辦到引用）：

- 套用到選取碰到的每一行。選取的終點停在某一行的開頭（拖選整行時常見）時，那一行不算在內。
- 選了好幾行時，中間的空行不加記號，但引用會在空行補一個 `>`，引言才不會從那裡斷開（同來源面板的引用鈕，`sourcepane.js`）。只有一行時空行照加：游標停在空行上按，就是要開始一個清單。
- **每一行都已經是這個狀態才拿掉**，否則全部補上。拿掉的是整個行首結構（清單記號連同方框）：方框前面沒有清單記號，就不是待辦了（§2.1 的判準）。
- 待辦與已完成只設定方框：沒有清單記號的行補上 `- `，已有的記號原樣留著（`1. [ ]` 也是待辦）。清單與編號只換清單記號，方框原樣留著。
- 行首結構的判讀跟渲染一致：方框後面必須是空白或行尾（`render.ts` 的 `TASK_RE`），所以 `[x](網址)` 是連結，不是標記。

**包住選取的三顆**（粗體到程式碼）：

- 選取兩端的空白留在記號外面：`**字 **` 不會變粗體，而雙擊選字時常常會連後面的空格一起選進去。
- 記號在選取外面或被選在裡面都認得，再按一次就拿掉。`*` 同時是斜體與粗體的字元，要看連著幾個：奇數個（`*`、`***`）裡有一層斜體，兩個以上裡有一層粗體。所以對 `**重點**` 按斜體，會得到 `***重點***`，不會拆掉粗體。
- 沒有選取時插入一對記號，游標停在中間；還沒打字就再按一次，這一對就收回去。

**按鈕不拿走焦點**：文字框的選取留著，手機的鍵盤也不會收起來。還沒點進過文字框就按的話，套用在最後一行（瀏覽器預設把游標放在最前面，那不是想要的位置）。

### 4.4 Enter 延續清單

在清單項目上按 Enter，下一行帶出同樣的縮排與記號：

| 這一行 | 按 Enter 之後的下一行 |
|---|---|
| `- [ ] 甲`、`- [x] 甲` | `- [ ] `（待辦的下一項一律從未完成開始：剛打下去的那一件不會已經做完） |
| `- 甲`、`  * 甲` | `- `、`  * `（縮排與記號照抄） |
| `1. 甲`、`9) 甲` | `2. `、`10) ` |
| `> - 甲` | `> - `（引言裡的清單） |

- 游標在字中間：後半段成為下一項。
- **空的一項再按一次 Enter，就結束清單**：那一行的記號拿掉。還在引言裡的話 `>` 留著；只是縮排的話，縮排一起拿掉。
- 以下照常換行：**Shift+Enter**（「我就是要換行」）、不在清單項目上、游標在記號前面（在行首按 Enter 是想把這一項往下推）、在程式碼區塊裡、有選取的時候、**輸入法還在組字時按的 Enter**（注音、倉頡選字時按的 Enter 是在確認組字）。
- 引言本身不延續：`> 甲` 按 Enter 就是一般的換行。單一換行就是換行（v2 E.4），引言裡的換行本來就排得出來。
- 後面的編號不會重排。Markdown 的編號清單只看第一項的數字，畫面上照樣是連續的。

### 4.5 實作

- **模板**：`src/web/views/mdbar.eta` 印出工具列（`role="toolbar"`、`aria-controls` 指向文字框），`new.eta` 與 `edit.eta` 在文字框前面 include 它。圖示放進 `icon.eta`（`md-task`、`md-done`、`md-bullet`、`md-ordered`、`md-quote`、`md-bold`、`md-italic`、`md-code`、`md-link`）。粗體與斜體也畫成圖示：黑體的斜體 I 只是一道斜線，看起來像「/」。
- **工具列不放進 `<label>`**：有工具列的欄位，外層從 `<label class="field">` 改成 `<div class="field">`，欄位名稱改成 `<label for>`。原因有兩個：label 的文字會成為文字框的名稱，按鈕放進去會一起被念出來；沒有 `for` 的 label 對應的是它裡面第一個可以標記的元素，也就是第一顆按鈕，點「內文」兩個字就等於按下「待辦」。`form.css` 的 `.field > label` 跟 `.field > span` 長得一樣。
- **`public/js/mdbar.js`**：
  - 改字一律用 `execCommand('insertText')`。這樣改的字會進瀏覽器的復原紀錄（Ctrl+Z 退得回去），也會自己發出 `input` 事件，草稿暫存（v2.2）不用另外通知。這個 API 已經被標成廢棄，但在文字框裡要改字又要保留復原紀錄，沒有別的辦法（`copy.js` 也是同樣的取捨）。它不能用的時候就直接改 `value`，再自己發一次 `input`，代價是復原紀錄斷在那一步。
  - 按鈕擋掉 `mousedown`，焦點就不會移走（觸控時是點完之後補發的那個 `mousedown`）。動作放在 `click`：手指按下去又滑開就不算數。
  - Enter 在 `keydown` 處理，跳過 `isComposing` 與 `keyCode === 229`。手機的虛擬鍵盤常常不給 `keydown` 真正的按鍵，這時改由 `beforeinput`（`insertLineBreak`、`insertParagraph`）處理；不能取消的那種不碰，否則會變成兩個換行。
  - 上半部是純粹的文字運算（輸入原文與選取範圍，交回「把哪一段換成什麼、選取落在哪裡」），不碰 DOM，掛在 `window.skynoteMd` 上給測試用。
- **樣式**：按鈕跟卡片頁的複製、下載（`card.css` 的 `.toolbtn`）同一個重量：沒有框、淡色，滑過去才浮起來。按鈕 32px 見方，彼此之間不留間距，九顆加兩道分隔線在 360px 寬的手機上排得進一列。

## 5. 帶入原卡的連結

### 5.1 動機

v3 §2.4 的 TODO 習慣是每天一張卡，從昨天那張按「更新」開出來。昨天那張連著還在進行的事（作業、專題、一則碎片），今天這張要再連一次，而每一條都得在連結欄搜標題、再挑出來。

光靠「更新」串起來不夠。卡片頁的上游預設只展開第一層（`routes.ts` 的 `UPSTREAM_OPEN = 0`），最多往回抓四層（`THREAD_DEPTH = 4`）。一件事如果只有五天前那張 todo 連著，在今天這張的上游串上展開也看不到。所以進行中的事本來就得每天直接連一次，這顆按鈕省掉的是搜尋那一步。

### 5.2 做法

- 從卡片頁 `+` 進來的表單（任何一顆動作按鈕），原卡有可以帶的連結時，「連結」右邊多一顆「帶入原卡的 N 條連結」。
- 按一下，原卡的連結全部加成一般的連結列：關係已經挑好（§5.3），右邊有 −，可以拿掉。指向原卡的那一條固定列（U16）不變。
- **全部帶入，再拿掉不要的**，不是一條一條挑（使用者裁決）：漏連比多連傷。沒連上的那件事，從新卡的上游串上就看不到了；多連的那條，頂多是上游串多一行。代價是忘了拿掉的那條會永久留著（R7：連結只增不減），所以帶進來的是送出前看得到、拿得掉的列，不在背後自動帶。
- 已經在表單上的目標不再帶一次，例如手動先加過的，或驗證失敗退回的表單。拿掉一列之後按鈕會回來，數字是還沒帶進來的那幾條；全部都在表單上時按鈕不顯示。
- 沒有原卡的入口（裸的 `/new`、隨手記的展開、追加外部資料）沒有這顆按鈕。沒有 JS 時也不顯示（`html:not(.js) .carrylinks`）。

### 5.3 哪些連結帶、用哪條關係

由 `present.ts` 的 `carryLinks` 決定，伺服器算好之後交給表單：

- **不帶原卡的 `updates`、`refutes`**：那一頭已經被原卡取代了，新卡再蓋一次章沒有意義。11/5 的 todo 更新了 11/4 的，11/6 的不會也去更新 11/4 的；「誰取代了誰」由新卡指向原卡的那一條接著講。
- 不帶找不到的目標，也不帶新卡的型別根本連不到的目標（例如重述連不到思考）。
- **關係沿用原卡的那一條**。新卡的型別不允許時，退到手動加一列時的預設值（`DEFAULT_REL`），再不行才取第一個合法的。退向弱的那一端，理由同 `DEFAULT_REL`：替使用者選一條有承諾的關係，等於做了一個他還沒做的判斷。`updates`、`refutes` 不在退路裡：帶入不該暗地裡讓任何一張卡從時間軸消失。
- 同一個目標只帶一次。原卡可能用兩條不同的關係指向同一張，換成新卡的型別之後可能落在同一條上，那就是規則擋下的重複。
- 目標在別的環境照樣帶（連結可以跨環境，v3.1）。

### 5.4 不受影響的地方

- **定案**：要帶的那幾張已經被原卡連著，早就定案了（R6），帶入不會多鎖住哪一張。
- **規則**：沒有新規則。帶進來的連結送出時照樣經過 R3 與重複檢查。
- **草稿**：連結列不存進草稿（v2.2），帶進來的列也一樣。重新整理之後要再按一次；手動加的列本來就是這樣。
- **目標卡的下游**：像「國文作業」這種一直連著的卡，下游會每天多一張 todo。被更新取代的 todo 在引用串裡照樣列著（§2.4）。手動連也是一樣，按鈕只是讓它累積得比較快。

### 5.5 改動檔案

| 檔案 | 改動 |
|---|---|
| `src/web/present.ts` | `carryLinks`：哪些連結帶、用哪條關係 |

| `src/web/views/new.eta` | 「連結」右邊的按鈕，`data-links` 帶著要加的列 |

| `test/v3.2.test.ts` | §5 的測試 |

### 5.6 測試

- **自動**（`test/v3.2.test.ts` 的 §5）：`carryLinks` 的取捨（沿用關係、不帶取代類、退路、同一目標只帶一次）；從卡片頁 `+` 進來時按鈕帶著哪幾條、原卡更新的那張不帶；帶進來的關係送得出去；裸的 `/new` 與沒有連結的原卡沒有按鈕；驗證失敗退回時按鈕還在。
- **瀏覽器**（headless Chromium，2026-11-06）：按一下全部帶進來、關係與標題正確；拿掉一列後按鈕回來、數字是 1，再按只帶回那一條；手動加一列挑了同一個目標，按鈕就收起來；驗證失敗退回時帶進來的列都在、按鈕不顯示；送出後新卡的上游串列著那幾張，檔案裡是一條 `updates` 加兩條 `related`；360px 寬時「連結」、＋ 與按鈕排在同一行。
