## 1. 時間軸的內文開頭

### 1.1 動機

文章不長的時候，在首頁多顯示一些，不必點進去才讀得完。

先前有兩道截斷：伺服器的 `excerpt()` 把內文壓平成 90 字並去掉換行，CSS 再截成兩行（v2.1 的 U34）。壓成一行之後，條列與分段的結構也一起消失，連認都不好認。只改 CSS 沒有用。

### 1.2 做法

**伺服器（`src/web/present.ts` 的 `excerpt()`）**，依序：

1. 程式碼區塊（` ``` ` 圍起來的）整段拿掉。
2. 逐行剝掉記號：引言的 `>`、標題的 `#`（`#` 後面要有空格才算標題，`#標籤` 開頭的一行照留）、強調與行內程式碼的 `*` `_` `` ` `` `~`；連結與圖片只留文字。
3. 條列的 `-` `*` `+`（含待辦的 `[ ]` `[x]`）換成「・」。編號清單照留。
4. 空行，以及分隔線、表格的對齊列（`|---|:-:|`）整行拿掉。
5. 取前 `EXCERPT_LINES`（5）行，以換行接起來；超過 `EXCERPT_CHARS`（300）字再截。有截到就以「…」收尾。字以碼位算，中文一個字算一個，換行也算一個。

列表上不渲染 Markdown：這裡要的是認得出這張卡，不是讀一份排好的文件。

**畫面（`src/web/views/cardlist.eta`、`public/css/list.css`）**：時間軸的內文開頭多一個 class `rowlines`，`white-space: pre-line` 排出換行，`-webkit-line-clamp: 8`。`.rowtext` 本身的兩行截斷（U34）不動，搜尋的命中片段照它。

**範圍**：時間軸，包含標籤、型別篩選與「已隱藏」（§2.3）。搜尋結果有命中片段時用片段，維持兩行。資料（`original`）的列照舊不顯示內文，改列出處（v2.1 U5）。碎片走同一支函式，它那段話一樣保留換行。

### 1.3 兩種「行」

原文的一行可能是一整段長文，在直式螢幕上會折成好幾行。所以有兩道限制，各管一件事：

- **伺服器的 5 行、300 字**算的是原文：保留前幾段的結構，不讓一張長卡把整份原文送進列表。
- **CSS 的 8 行**算的是畫面：一段長文在窄欄裡折行之後，不會把一列撐得太高。

兩個數值都是常數（`EXCERPT_LINES`、`EXCERPT_CHARS`、`list.css` 的 `.rowlines`），用一陣子再調。

## 2. 已被更新或反駁的卡

### 2.1 動機

首頁上，「我現在怎麼想」跟「我以前這樣想、後來推翻了」排在一起，舊卡沒有任何記號。要點進舊卡、捲到最下面的引用串，才看得到「被反駁」或「更新出」。這帶來兩件事：時間軸變雜，而且讀到舊卡時會以為它還成立。

本版之後，**時間軸列的是目前還成立的卡**，不再是寫過的全部。被取代的卡不刪、不改，只是不列在時間軸上；從篩選列、搜尋、引用串都還找得到。

### 2.2 判準

**一張卡只要有任何一條 `updates` 或 `refutes` 指向它，就算已被取代。**

- **`contradicts` 不算**：它說的是兩者不相容、還沒裁決，誰也沒推翻誰。
- **不往回推**：A 被 B 反駁、B 又被 C 反駁，A 不會因此回到時間軸。系統判斷不了 C 推翻的是 B 的哪一部分；要讓 A 回來，就發一張新卡。
- **碎片的「完整化」也算**：它走的就是 `updates`（v2 的 CARD_ACTIONS）。完整化過的碎片從時間軸上消失，這是想要的效果——那段話已經長成一張思考了。
- **跨環境也算**：連結可以跨環境（v3.1 §2.5）。B 在環境 Y、更新了環境 X 的 A，X 的時間軸一樣不列 A；A 的卡片頁提示會連到 B，並標出 Y。
- **寫不進卡片檔**：舊卡被新卡指著，R6 已經把它鎖住（I2 也不允許）。「已被取代」是索引上的一個查詢，每次從 `links` 表算出來：`NOT EXISTS (SELECT 1 FROM links WHERE target_id = c.id AND rel IN ('updates', 'refutes'))`，走既有的 `idx_links_target`。schema 不變，不需要重建索引。

判準的唯一真相來源是 `src/domain/types.ts` 的 `SUPERSEDING_RELS`。

### 2.3 時間軸與篩選列

- **時間軸不列**：首頁、標籤的時間軸（`/?tag=…`）、型別篩選（`/?type=…`）都不列已被取代的卡。篩選列右端的總數與分頁也不算它們。
- **篩選列多一個「× 已隱藏」**，排在碎片右邊。型別前面是色點，這一格前面是一個 ×（`icon.eta` 的 `x`，淺灰），不顯示數量。這個環境（有選標籤時是這個標籤）裡沒有已被取代的卡，這一格就不出現。
- **點下去（`/?hidden=1`）只列已被取代的卡**，同樣依時間逆序、同樣帶著標籤。它跟型別篩選是同一排互斥的選項：網址同時帶 `hidden=1` 與 `type` 時只認「已隱藏」。
- **「全部」名字不變**：它不含已隱藏的卡，但不改名。
- **側欄的最近卡片**（v3 §5）也不列。

### 2.4 不受影響的地方

- **標籤頁的計數照算被取代的卡**（使用者裁決）：那個數字記的是在這個話題上打轉了幾次，不是現在還成立的有幾張。所以標籤頁寫「#物理 5」、標籤的時間軸列 3 張是正常的，差的兩張在那個標籤的「已隱藏」裡。表單的標籤推薦用同一份計數，也照算。
- **搜尋**照樣列，也不另外標記：找舊卡是搜尋的用途之一。點進去之後卡片頁會說它已被取代。
- **引用串與連結的選卡器**照樣列。
- **側欄的環境排序**（卡片數、最近一張的時間，v3.1 §2.8）照算。

### 2.5 卡片頁頂端的提示

已被取代的卡，卡片頁的**第一行**是一塊淺紅底的提示，排在標題之上：

```
本文已被更新：〈新版的標題〉、〈另一個新版〉
本文已被反駁：〈反駁它的那張〉
```

- **說法**：`updates` 是「本文已被更新」；碎片被 `updates` 指到時是「已完整化」；`refutes` 是「本文已被反駁」。說法之後接全形冒號，再列出卡片。更新在前、反駁在後，同一種有好幾張時全部列出，以頓號隔開。
- **只列直接指過來的那幾張，不追到鏈尾**：A ← B ← C 時，A 的提示連到 B，B 的提示再連到 C。
- 標題嵌在句子裡，所以截到 24 字（同「已從 X 建立」，見 `present.ts` 的 `clip`）。另一頭在別的環境時，標出那個環境名。
- **樣式**：底色 `--superseded-bg`（`#FCE6E3`，新 token），標示字用 `--alert`（錯誤訊息的磚紅），連結加底線。底色左右溢出 `--hover-bleed`，文字左緣仍跟標題對齊。
- 提示是渲染時從反向連結算的（`routes.ts` 本來就為了下游的筆數查 `backLinks`，現在共用那一次查詢）。

## 3. 網路字型改回每一種裝置都載

**做法**：`layout.eta` 的 Google Fonts 樣式表拿掉 `media="(pointer: coarse)"`，電腦與手機都載 Noto Sans TC。

**理由**（使用者）：全局一致的行為。電腦與手機用同一份字型，不再依裝置分岔。

**代價**：v3.1 §4.3 量過，電腦上不載網路字型時，Ferdium 換頁露出黑格的比例從 5 / 12 降到 1 / 24。那時的原因是：字型切成十幾個字檔，每換一頁都要在畫第一格之前重新解碼。§4.4 的換頁不換文件（nav.js）之後才上線，字型解碼還會不會造成一閃，本版沒有重新量。如果又看到閃，這是第一個要查的地方。

**測試**：`test/v3.1.test.ts` 原本要求這個樣式表帶著 `media="(pointer: coarse)"`，改成要求它不帶 `media`。模板裡的樣式表只能是網路字型、自己的 CSS 嵌進頁面，這兩條照舊。
